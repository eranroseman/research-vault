# Prior art: trust gates & the citation-check suite (enforcement machinery)

Research note, 2026-08-16. Feeds decision ticket #10 (eranroseman/knowledge-harness): where each mechanical check runs (Claude Code hooks / skills / pre-commit / CI) and which fail open vs closed. Scope is the **checking/enforcement machinery only** — the provenance schema and the Zotero data flow are sibling notes. The checks under decision are the six from research/prior-art/prior-art-knowledge-work-harness.md §5–6: citekey-exists lint, DOI existence, metadata match, retraction check, quote verification, factored verification. Pandoc behavior was live-verified 2026-08-16 on pandoc 3.1.3; Claude Code hook semantics were verified against the official raw docs the same day.

## Summary

Every mature prior-art system converges on the same doctrine: **detection always-on and free; enforcement opt-in per surface; fail-closed only at a publish/merge boundary, always with a documented bypass.** Manubot ships fail-open with a one-line opt-in to strict (`manubot-fail-on-errors`); pandoc warns-and-continues on a fabricated citekey unless `--fail-if-warnings`; Vale fails CI only on its top severity tier and ships `--no-exit`; the lychee GitHub Action flipped its default from open to closed in v2 after users found fail-open surprising; Imbad0202's citation gate detects universally but blocks only under an opt-in strict policy; pre-commit is bypassable by design (`--no-verify`) while GitHub required status checks are the only truly closed surface. For quotes, nobody sane does byte-exact matching against PDF text — W3C mandates normalize-then-exact, Hypothes.is layers fuzzy fallbacks for *recall* (a tolerance a trust gate must not inherit), and unverifiable quotes surface honestly as orphans rather than silently passing. Claude Code's hook events give the harness deterministic warn surfaces (PostToolUse), a deterministic block surface (PreToolUse), and a turn-boundary gate (Stop, bounded at 8 consecutive blocks) — five of the six checks are deterministic and free; only factored verification is LLM-costed and belongs at explicit boundaries.

## #1 Manubot — citation-by-identifier, build-as-gate

**Mechanism.** Manuscript text cites persistent identifiers directly — `[@doi:10.1098/rsif.2017.0387]`, `[@pubmed:29424689]`, `[@pmc:PMC5640425]`, `[@arxiv:1806.05726]` — and the `pandoc-manubot-cite` filter resolves them to bibliographic metadata at build time (https://github.com/manubot/manubot; active). This *dissolves* the citekey-fabrication class: the identifier is the citation, so the failure mode shifts to "identifier does not resolve," which is mechanically catchable. The Manubot paper states the gate model plainly: "Using CI to build the manuscript automatically catches many common errors, such as misspelled citations, invalid formatting, or misconfigured software dependencies" and "If this process is error free, the CI service timestamps the manuscript and uploads the output files" (https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1007128; PLOS Comp Biol 2019, DOI 10.1371/journal.pcbi.1007128).

**Error/severity model — fail-open default, one-line strict opt-in.** "By default, `pandoc-manubot-cite` does not fail upon invalid citations, although this can be changed by adding the following to `metadata.yaml`: `pandoc: manubot-fail-on-errors: true`" (https://github.com/manubot/rootstock/blob/main/USAGE.md; rootstock main, read 2026-08-16). Unresolvable metadata has a first-class human override: files matching `manual-references*.*` supply manual metadata, and "Manubot uses the supplied metadata and does not attempt to generate it" (same source) — the escape hatch is data, not a flag.

**Placement/maturity.** CI-only (GitHub Actions builds per push/PR); mature, actively maintained, in production for real papers. The pattern to port: build-time resolution in CI as the *earned* closed gate, manual-references as the documented bypass.

## #2 Pandoc/Quarto citeproc as a gate

**Live-verified (pandoc 3.1.3, 2026-08-16).** A document citing `[@fakekey2026]` against an empty bibliography: `pandoc doc.md --citeproc --bibliography=refs.bib` prints `[WARNING] Citeproc: citation fakekey2026 not found`, **exits 0**, and renders the citation as `(<strong>fakekey2026?</strong>)` — a visible artifact, but a successful build. Adding `--fail-if-warnings` prints `Failing because there were warnings.` and **exits 3**. The manual documents the flag ("Exit with error status if there are any warnings") and exit code 3 as `PandocFailOnWarningError` (https://pandoc.org/MANUAL.html; the missing-citekey rendering itself is *not* documented in the manual — live test is the evidence). So: **a vanilla build cannot fail on a fabricated citekey; one documented flag makes it fail closed.** This is the zero-code CI gate for the citekey-exists check — it needs only the BBT auto-exported bibliography from §4 of the sibling note. One caveat: `--fail-if-warnings` fails on *any* pandoc warning, not just citeproc's, so Obsidian-flavored notes that trigger unrelated warnings would false-positive — the thin-lint-over-CSL-JSON alternative in the gate table avoids that.

**Quarto.** Quarto delegates citation processing to Pandoc/citeproc ("Quarto will use Pandoc to automatically generate citations and a bibliography," https://quarto.org/docs/authoring/citations.html) and its citations docs expose **no strictness/validation options**. `quarto render --fail-if-warnings` exists but issue #493 (https://github.com/quarto-dev/quarto-cli/issues/493; opened March 2022, still open, milestone "Future") shows Quarto's own warnings do not trigger a non-zero exit; whether pandoc-citeproc warnings propagate through the flag is unverified — treat Quarto as no better than bare pandoc for gating.

## #3 Prose linters as CI precedent — severity tiers and fail conventions

**Vale — the three-tier severity model.** Rules carry a `level`: "The available options are `suggestion`, `warning`, and `error`" (default `suggestion`) (https://docs.vale.sh/topics/styles; read 2026-08-16). Exit codes: "`0` — No error(s) were found. `1` — Linting error(s) were found. Useful for failing CI builds; can be disabled with `--no-exit`. `2` — Runtime error(s) occurred" (https://docs.vale.sh/topics/cli; read 2026-08-16 — note vale.sh/docs/cli 301s here). `--minAlertLevel` raises the reporting floor. The precedent: **only the top tier fails the build, and the opt-out (`--no-exit`) is explicit, not silent.** Note Vale separates "check found problems" (1) from "check itself broke" (2) — the same distinction Imbad0202 encodes as UNMATCHED vs UNREACHABLE (§6).

**lychee — link checking, and a default that flipped closed.** Exit codes: 0 success, 1 missing inputs/runtime/config failures, 2 "Link check failures. At least one non-excluded link failed the check," 3 config-file errors (https://github.com/lycheeverse/lychee). Flakiness affordances are extensive because network checks are inherently flaky: `--max-retries` (default 3), `--accept` status-code ranges (e.g. `200..=204, 429`), `.lycheeignore` regexes, response caching. The GitHub Action's v2.0.0 release **flipped `fail` from default-open to default-closed**: "pipelines will now fail on broken links automatically. This addresses user feedback that not failing on broken links was unexpected" (https://github.com/lycheeverse/lychee-action/releases/tag/v2.0.0; published 2024-10-08, timestamp verified via the GitHub releases API 2026-08-16). Current `action.yml` on master: `fail` default `true`, `failIfEmpty` default `true` (https://github.com/lycheeverse/lychee-action/blob/master/action.yml, read 2026-08-16). The README still demonstrates the asynchronous pattern for scheduled runs: daily cron + "create an issue in case of errors" (https://github.com/lycheeverse/lychee-action). markdown-link-check (https://github.com/tcort/markdown-link-check) offers the same affordances (`retryOn429`, `aliveStatusCodes`, `ignorePatterns`) but does not document exit codes in its README — lychee is the better-specified precedent.

**Doctrine payload.** Prose CI matured into: deterministic offline lints fail closed cheaply; network-dependent checks earn fail-closed only with retries/accept-lists/ignore files as escape hatches; scheduled-issue mode exists precisely so link rot (which happens *to* you, not *by* you) doesn't block unrelated work. And the ecosystem's direction of travel — lychee v2 — is toward fail-closed defaults once the escape hatches exist.

## #4 Quote-verification tolerance — normalize-exact, fuzzy-warn, never silent-pass

**The spec baseline.** W3C Web Annotation Data Model (Recommendation, 2017-02-23) defines TextQuoteSelector as `exact` + recommended `prefix`/`suffix`, with normalization mandatory at record time: "The text MUST be normalized before recording in the Annotation" (tags removed, entities decoded); multiple matches "SHOULD be treated as matching all of the matches"; the spec contains **no approximate-matching guidance** — it is normalize-then-exact (https://www.w3.org/TR/annotation-model/#text-quote-selector).

**Hypothes.is — fuzzy anchoring in practice.** The 2013 design post describes four ordered strategies — range selector, position selector, context-first fuzzy, selector-only fuzzy — using "a modified version of the google-diff-match-patch library, which uses the Bitap matching algorithm for text matching," accepting matches "if the difference is within a given acceptance threshold" (https://web.hypothes.is/blog/fuzzy-anchoring/; 2013-04-22). The current client (main branch, read 2026-08-16) uses the `approx-string-match` library with `const maxErrors = Math.min(256, quote.length / 2)` — up to **50% of the quote may mismatch** — and composite scoring `quoteWeight = 50, prefixWeight = 20, suffixWeight = 20, posWeight = 2`, exact search tried first (https://github.com/hypothesis/client/blob/main/src/annotator/anchoring/match-quote.ts). For PDFs the client strips ASCII whitespace before matching because "text extracted from a PDF by different PDF viewers, including different versions of PDF.js, can often differ in the whitespace between characters and words," and compares NFKD-normalized strings to absorb Unicode-normalization drift between extractor versions (https://github.com/hypothesis/client/blob/main/src/annotator/anchoring/pdf.ts) — first-party confirmation that whitespace and Unicode-form noise are the dominant extraction artifacts. Crucially, anchoring failures are surfaced honestly: unanchorable annotations appear in an "Orphans" tab (client 1.2.0) rather than being silently dropped or force-attached (https://web.hypothes.is/blog/showing-orphaned-annotations/).

**Plagiarism-detection normalization.** The MOSS/winnowing paper states the canonical requirement: "a copy-detection algorithm should have three properties: 1. Whitespace insensitivity — In matching text files, matches should be unaffected by such things as extra whitespace, capitalization, punctuation, etc." (Schleimer, Wilkerson & Aiken, SIGMOD 2003, https://theory.stanford.edu/~aiken/publications/papers/sigmod03.pdf; quote extracted from the PDF's raw streams 2026-08-16 — the fetcher's own text extraction failed on it, a live demonstration of the problem class).

**Defensible tolerance policy (candidate, not a decision).** Hypothes.is's 50%-error tolerance optimizes *recall* in an annotation UX where a misplaced highlight is cheap. A trust gate inverts the cost structure: the expensive error is a false PASS. The defensible port: (a) normalize both sides — Unicode NFKC (folds fi/fl ligatures), collapse whitespace runs, remove soft hyphens and line-break hyphenation — then require **exact match = pass**; (b) approximate match above a strict threshold = **warn + human review queue** (the orphans pattern), never a silent pass; (c) no match = fail. The three-state outcome mirrors Hypothesis (anchored / orphaned / gone) and Vale's tiers; the one forbidden outcome is fuzzy-match-reported-as-verified.

## #5 Claude Code enforcement surfaces, pre-commit, and CI

All hook claims from the official docs, fetched as raw markdown 2026-08-16 (https://code.claude.com/docs/en/hooks.md and https://code.claude.com/docs/en/hooks-guide.md; key rows independently spot-checked). Hooks are the deterministic layer: they give "deterministic control: certain actions always happen rather than relying on the LLM to choose to run them" (hooks-guide) — versus skills/CLAUDE.md, which the model *chooses* to follow.

- **PreToolUse** — can block: exit 2 "Blocks the tool call"; JSON `hookSpecificOutput.permissionDecision` ∈ `allow`/`deny`/`ask`/`defer` (precedence `deny > defer > ask > allow`). The only surface that can stop a fabricated citekey **before it lands in a file** — at the cost of running on every matched tool call.
- **PostToolUse** — cannot block: exit 2 "Shows stderr to Claude; the tool already ran"; JSON `decision: "block"` attaches a `reason` beside the tool result (feedback that steers Claude to fix, not an undo), plus `additionalContext`/`updatedToolOutput`. Matchers filter by tool (`Edit|Write`). This is the natural warn-tier lint surface for .md edits.
- **Stop / SubagentStop** — can block: exit 2 "Prevents Claude from stopping, continues the conversation"; JSON `decision: "block"` with required `reason`. Inputs include `stop_hook_active` to detect re-entry, and "Claude Code overrides the hook and ends the turn after 8 consecutive blocks" — a built-in liveness bound every fail-closed gate should envy. This is the turn-boundary receipts gate.
- **UserPromptSubmit** — can block and erase a prompt; can inject `additionalContext`.
- **SessionStart** — cannot block; injects context via stdout or `additionalContext`; matchers `startup`/`resume`/`clear`/`compact`/`fork`. Policy-injection surface.
- Command hooks default to a 600 s timeout (not 60); prompt-based and agent-based hooks exist "for decisions that require judgment rather than deterministic rules" — i.e., the docs themselves draw the deterministic-vs-LLM line the gate inventory needs (hooks-guide).

**pre-commit framework.** Hooks run at commit; "The commit will be aborted if there is a nonzero exit code" — but bypass is by design: `SKIP=<hook-ids>` env var or `git commit --no-verify` (https://pre-commit.com; read 2026-08-16). The docs' own answer is to replay in CI: "adding `pre-commit run --all-files` as a CI step will ensure everything stays in tip-top shape." So a local pre-commit gate is *convenience enforcement* — fast feedback, honest-by-consent — never the trust boundary.

**GitHub Actions as the vault-repo gate.** Required status checks are the only genuinely closed surface: "Required status checks must have a `successful`, `skipped`, or `neutral` status before collaborators can make changes to a protected branch" — noting admins bypass by default unless "Do not allow bypassing the above settings" is set (https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches). Two caveats for our substrate: `skipped` counts as passing (so path-filtered jobs weaken the gate), and a personal vault pushed straight to main never crosses a PR boundary — in that topology the Stop-hook publish gate and scheduled CI are the real enforcement points. Scheduled Actions fit the lychee daily-issue pattern exactly: the nightly Retraction Watch CSV batch (free, offline, from the GitLab repo per the sibling note) belongs there, filing an issue/inbox note rather than failing anyone's push.

## #6 Existing citation-verification gate implementations

**Imbad0202/academic-research-skills — the closest existing deterministic gate** (https://github.com/imbad0202/academic-research-skills; v3.20.1, 2026-08-15; **CC-BY-NC 4.0 — mechanism studied, not copied**). Implementation read from `scripts/verification_gate/__init__.py` (the whole gate is that one module) plus README/changelog:

- **Placement:** mandatory integrity checkpoints at pipeline stage boundaries (stages 2.5 and 4.5) — boundary-placed, not keystroke-placed.
- **Mechanism:** four resolvers in parallel — Crossref and OpenAlex (DOI-first, then title), Semantic Scholar (entry-keyed, DOI-first internally), arXiv (only when an arXiv ID exists, else SKIPPED).
- **Four internal statuses:** `MATCHED` / `UNMATCHED` / `UNREACHABLE` / `SKIPPED`. API outages map to `UNREACHABLE` via per-resolver exceptions, and unavailable resolvers "do not veto a match from available ones" — **outage is never reported as fabrication.** Public result is three-state: `lookup_verified` true / false / `"unresolvable"` (legitimately unindexed humanities/regional works — the gate admits index-coverage limits rather than over-claiming).
- **Human override is first-class:** entries with `obtained_via == "manual"` skip all resolvers.
- **Caching:** persistent SQLite (`~/.cache/ars/verification.db`, 90-day TTL) with staleness-advisory metadata that is "advisory metadata, never a gate input," and env-var-controlled revalidation.
- **Enforcement split:** detection runs universally; terminal blocking only under opt-in `terminal_policies.citation_existence == strict` (default advisory, acknowledgeable via `/ars-mark-read`). Changelog rationale: "a fabricated citation with a provably-bogus DOI/arXiv ID is caught by lookup rather than by hoping a reviewer agent notices."
- Adjacent: citations carry three-layer anchors (quote ≤ 25 words, page, section) attached at emission for later audit, and an opt-in LLM claim-faithfulness audit (`ARS_CLAIM_AUDIT=1`) — their deterministic/LLM boundary matches ours.

**scite Reference Check** (commercial; scite.ai blocks automated fetch — claims via help-desk/blog snippets, consistent with the sibling note): upload a manuscript PDF; ML identifies references and matches citation statements; flags retractions and editorial notices "utilizing data from Crossref, Pubmed, and Retraction Watch," with supporting/disputing/mentioning breakdowns per reference (https://help.scite.ai/en-us/article/how-do-i-use-the-scite-reference-check-xo6fv5/; https://scite.ai/blog/reference-check-an-easy-way-to-check-the-reliability-of-your-references-b2afcd64abc6). It is a **report, not a blocker** — advisory output for authors/editors/reviewers at the submission boundary; premium feature.

**JATS4R** (one paragraph, as scoped): a NISO working group publishing best-practice recommendations for JATS XML (including data citations), with a web validator that checks documents against JATS DTDs plus "recommendations that have been published on the JATS4R website," implemented as a web service with Schematron rules (https://jats4r.niso.org/; https://jats4r.niso.org/jats4r-validator/). Its severity taxonomy was not confirmable from the fetched pages. Precedent value: publisher-side submission checking is likewise a boundary-placed validation *report* against published rules — nobody blocks authoring keystrokes.

## #7 Fail-open vs fail-closed doctrine, ported

Our own dev-harness analysis already states the doctrine (research/harness-audits/dev-harness-analysis.md, "Hooks and crons"): PostToolUse regex passes are "Warnings, fail-open"; the opt-in press-check publish gate on Stop "fails closed; manual bypass documented"; "Everything else fails open — a harness feature must never cost the session"; crons are "loud on their own failure." Every external system surveyed independently converges on the same shape: Manubot (open by default, one-line strict opt-in, data-shaped bypass), pandoc (warn + visible artifact, flag-gated failure), Vale (top-tier-only fails CI, explicit `--no-exit`), lychee-action (escape hatches first, then the default flipped closed), Imbad0202 (detect always, block opt-in, outage ≠ fabrication), pre-commit vs required status checks (bypassable local convenience vs closed merge boundary), Hypothesis (unverifiable ≠ discarded — orphaned).

The ported doctrine, as principles for ticket #10:

1. **Fail-closed is earned at publish/merge/stop boundaries, never at keystroke time.** Interactive surfaces warn and steer; boundaries block.
2. **Detection is always-on and free; enforcement is a per-surface policy knob** (Manubot/Imbad0202 pattern).
3. **"Check failed to run" must be a distinct state from "check ran and failed."** UNREACHABLE warns and retries; only UNMATCHED/mismatch can justify a block. A network outage must never brick a session (fail-open on infrastructure) — though a *publish* gate may legitimately refuse to pass on UNREACHABLE (fail-closed on uncertainty) because publishing can wait.
4. **Every closed gate carries a documented bypass and a liveness bound** — Manubot's manual-references, Vale's `--no-exit`, pre-commit's `--no-verify`, Claude Code's 8-consecutive-block cap. A gate without a bypass gets deleted by its users; a gate without a bound eats the session.
5. **The forbidden outcome is the silent pass** — a fuzzy quote match reported as verified, a skipped check reported as green (`skipped` counting as success in GitHub required checks is the cautionary spec).

Cost: "free" = no LLM tokens; APIs below are the free pipeline from the sibling note (§5). Surfaces: **H** = Claude Code hook (event named), **S** = skill, **P** = pre-commit, **C** = CI (GitHub Actions).

| Check | Deterministic? | Candidate surfaces | Fail-open/closed candidate | Cost |
|---|---|---|---|---|
| Citekey exists in bibliography | Yes — offline, zero flake | H:PostToolUse(Edit\|Write) warn; P; C (`pandoc --citeproc --fail-if-warnings` or thin lint over BBT CSL-JSON) | Open (warn) interactively; **closed** at P/C — offline determinism earns it | Free, ms |
| DOI existence (doi.org handle API) | Yes — network | S (at citation-add); H:Stop batch on turn's delta; C | Open interactively; **closed at publish gate** on UNMATCHED only; UNREACHABLE = warn/retry, never "fabricated" | Free API |
| Metadata match (Crossref vs draft citation) | Mostly — needs a title/author comparison tolerance (same normalization discipline as quotes) | S (at ingest); C batch | Open (mismatch → review queue); block only on gross mismatch at publish, policy-gated | Free API |
| Retraction (Crossref `updated-by` live; RW CSV batch) | Yes — live=network, CSV=offline | S (at ingest); C nightly scheduled (CSV, lychee-style issue filing); H:Stop at publish | Open as standing alert; **closed at publish** for unacknowledged retracted citations, with an explicit acknowledge-tag bypass | Free (CSV offline) |
| Quote verification vs source text | Yes, *given* a normalization policy — local CPU once source text is on disk | S (at extraction, the cheapest moment); C batch; H:Stop at publish | Normalize-exact = pass; fuzzy = **warn queue** (orphans pattern); miss = fail; **closed at publish**, open elsewhere | Free, local; requires PDF/text availability |

## Implications for ticket #10 (human decisions; defaults recommended, nothing decided)

1. **Interactive citekey lint: PostToolUse-warn or PreToolUse-block?** Recommended default: PostToolUse warn (fail-open, steers the model to fix); revisit PreToolUse blocking only if warnings measurably fail to prevent fabricated keys landing. PreToolUse is the deterministic pre-landing block, but taxes every edit.
2. **Is pre-commit worth having when `--no-verify` exists?** Recommended default: yes, as fast convenience enforcement (offline checks only), with CI replaying the same checks as the honest layer — the pre-commit docs' own pattern.
3. **What is the closed gate in a no-PR vault topology?** If the vault pushes straight to main, required status checks never bite. Recommended default: the Stop-hook publish gate (press-check pattern, fails closed, documented bypass, 8-block bound) is the trust boundary; CI is the async auditor (scheduled RW CSV batch → inbox issue). Decide whether "publish" is defined as a skill action, a branch merge, or both.
4. **Outage policy at the publish gate:** may the gate pass on UNREACHABLE? Recommended default: no — publishing waits for the check (fail-closed on uncertainty at that one boundary); everywhere else UNREACHABLE only warns. Requires the Imbad0202-style four-state result so the gate can tell outage from fabrication.
5. **Quote tolerance numbers:** which normalization set and what fuzzy threshold separates warn from fail. Recommended default: NFKC + whitespace-collapse + dehyphenation, exact-after-normalization = pass; any fuzzy-only match = warn queue, never pass. Explicitly reject anchoring-grade tolerance (Hypothesis's 50% error budget) for gate use.
6. **Retraction severity:** warn or block when a draft cites retracted work? Recommended default: block at publish only, with a first-class acknowledge mechanism (citing a retraction *as* a retraction is legitimate scholarship — the bypass must be data, like Manubot's manual-references, not a flag that disables the check).
7. **Factored-verification placement and budget:** which boundary (draft→review recommended), what per-run token budget, and whether its verdicts can ever block (recommended: no — adjudicated findings only).
8. **Per-gate bypass + bound inventory:** for each closed gate adopted, name its bypass artifact and its liveness bound before enabling it — the doctrine says a gate lacking either is a defect.

## Dead ends / negative knowledge

- **Pandoc's manual does not document missing-citekey behavior** — neither the warning text nor the `(**key?**)` rendering; only the live test establishes them. Cite behavior by version (verified on 3.1.3; newer pandoc not tested).
- **Quarto has no citation-strictness surface**: the citations docs expose none; `quarto render --fail-if-warnings` demonstrably ignores Quarto's own warnings (quarto-dev/quarto-cli#493, open since 2022-03, milestone "Future"); whether it propagates pandoc citeproc warnings is unverified. For gating, use pandoc directly.
- **Manubot's README omits its failure model** — `manubot-fail-on-errors` and the manual-references fallback are documented only in rootstock's USAGE.md.
- **README summaries lie about defaults**: a fetch of lychee-action's README reported `fail` default `false`; master `action.yml` says `true`. Always verify defaults in the machine-read artifact (action.yml), not prose. (Search also failed to surface the v2 flip — only the v2.0.0 release notes themselves state it.)
- **Imbad0202's gate is one module**: `scripts/verification_gate/` contains only `__init__.py`; the directory listing suggests more structure than exists. CC-BY-NC 4.0 stands — patterns only.
- **scite remains fetch-blocked** (consistent with the sibling note): Reference Check claims rest on help-desk/blog search snippets; no API/automation surface for Reference Check was found in public docs.
- **JATS4R validator severity taxonomy unconfirmed** — the site names Schematron and DTD validation but the fetched pages never enumerate error/warning tiers.
- **W3C TextQuoteSelector has no approximate-matching guidance** — fuzzy behavior is entirely implementation lore (Hypothesis client is the reference implementation in practice).
- **The winnowing paper's PDF defeats naive extraction** — WebFetch's converter returned compressed streams; the normalization quote had to be recovered by decompressing the PDF's content streams. PDF-extraction noise is real enough to have bitten this research note about PDF-extraction noise.
- **markdown-link-check does not document exit codes** in its README; lychee does — prefer lychee as the specified tool and precedent.
- **code.claude.com/docs/en/hooks.md truncates under the HTML fetcher** — the raw `.md` fetch is required for the full exit-code and decision-control tables; `stop_hook_active` and the `permissionDecision` enum appear only in the full document (verified 2026-08-16 via full raw fetch; spot-check of the exit-code table rows and timeout defaults confirmed independently).
- **Hook timeout folklore is wrong**: command hooks default to 600 s, not 60 s (60 s is the *agent*-hook default) — matters when a hook wraps a network check.
