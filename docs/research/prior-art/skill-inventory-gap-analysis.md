## 0. The candidate set under evaluation (proposed, NOT decided)

Six user-typed entry points (`disable-model-invocation: true`), two model-invoked guard/reference
skills (also user-invocable), hooks per #10:

| Component              | Kind                            | One-line charter (as understood from #7–#10)                                                                                                                       |
| ---------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `vault-setup`          | entry point                     | Scaffold vault repo from template (#7 layout), provision BBT auto-export via JSON-RPC `autoexport.add`, write vault AGENTS.md, install hooks (#8, #10)             |

### Part A synthesis

**Structural gaps (ranked):**

1. **Bridge maintenance has no owner** (5.2, 5.4, 5.5) — rename propagation, managed-region
   regeneration, provisioning repair. The mechanisms are all designed in #8; no skill runs them.
2. **Inbox/triage has no owner** (2.2, 5.8) — both the literature hit-list decision loop and the
   CI findings inbox fill with nothing that drains them.
3. **Re-orientation has no owner** (6.1) — mitigable by convention + shipped Bases, fully served
   only by personal skills the plugin can't depend on.
4. **Claim-first discipline placement is undecided** (3.2) — format is guarded, the Iron Law is not,
   unless `evidence-conventions` is explicitly scoped to carry it.
5. **Cross-cutting daily-log append contract is unowned** (2.7, 3.8, 6.2) — every entry point must
   write it; nothing says so yet.

**Honest frictions (not gaps):** manual citekey pinning at any scale (1.6, 2.6); human-executed
Zotero admission wrapped in a skill (2.3); guard-skill reliability rides on description matching
until #12 settles activation (3.4); two verification entry points to choose between (4.6);
`vault-setup` accretes wizard-style human rails (1.2).

**Overlaps:** all found overlaps are deliberate defense-in-depth per #10 doctrine (hooks vs
`verify-citations` vs `publish` re-running the same checks at different enforcement strengths) —
plus one seam to name explicitly (`vault-setup` vs `import-source` on batch backfill, 1.4).

### Personal-skill coverage and the distribution tension

Serving knowledge work **unchanged, today, from `~/.claude/skills/`**: `grilling` (thesis
interrogation), `domain-modeling` (glossary + decision records), `handoff` (session baton),
`wayfinder` (multi-session maps — this repo's own process runs on it), `research` (delegated
reading), `teach`, plus `to-questionnaire`, `wait-what`, `triage` (partially), `wizard`,
`consistency-audit`. The foundation plugin should **not** duplicate any of them for the author's
own use.

**The tension:** a shareable plugin cannot depend on personal skills — they are not distributable
and `skillOverrides`-style tuning does not reach plugin skills anyway (packaging research §2.4).
Public *plugins* (obsidian, codex, writing-clearly-and-concisely) are different: `plugin.json`
has a documented `dependencies` field (other plugins, optional semver — packaging research §1.3),
so a declared dependency on the obsidian plugin is plausible, **but whether it auto-installs or
merely records intent is unverified** — verify before relying on it in #15. Three postures, HITL:

- **(a) Self-sufficient trust core** — the plugin ships only the candidate set; personal skills are
  documented as optional enrichment ("works better with grilling/handoff/wayfinder installed"),
  never hard-depended on. Cold resume and thesis interrogation degrade gracefully for other users.
- **(b) Companion pack later** — knowledge-worded ports of handoff/wayfinder/grilling as a second
  plugin when the full arc ships.
- **(c) Declared plugin dependencies only** — depend on obsidian (and optionally codex) as public
  plugins; keep personal skills out of the dependency graph entirely.

Recommended default: (a) now, (b) revisited at the full arc, with the obsidian dependency from
(c) verified and declared if it resolves.
