# Declare, provision, observe: the Zotero and Obsidian components research-vault cannot pin, and how it sees what they do

Status: **draft, in brainstorming** (2026-10-04). Sections are recorded here as the operator approves them; the spec is not yet reviewed. Evidence siblings: `2026-10-03-substrate-components-design-zotero-screen-evidence.md` (screen A, Zotero add-ons), `…-obsidian-screen-evidence.md` (screen B, seam-free Obsidian plugins), `…-obsidian-zotero-screen-evidence.md` (screen C, Obsidian plugins that read Zotero). The verdicts are this spec's; the evidence carries per-must results only.

## Shape of this spec (decided 2026-10-04)

**One spec, one argument:** decision 12's three legs for the components research-vault cannot pin — declare, provision, observe — with *observe* covering both a component's state (doctor) and its effects (machine-surface detection and the capture monitor). Rulings 5 and 6 exempt ordinary editing and commands on the selection only because research-vault sees every change to what it owns, so the detection work and the declarations it licenses belong in one document.

**Plans are the plan writer's call; one ordering constraint binds them:** the detection and capture-monitor work lands before the seeded `.obsidian/` ships, and #190 (doctor's preference grammar) and #193 (prevent or detect machine-surface writes by agents) land before lane 4 opens.

**Lane 4 keeps annotation handling** (operator, 2026-10-04, #18): assembly decision 28 stands, and the ingest spec's `:137` claim to supersede it is amended in this spec's commits. #18's surviving requirement — pass Zotero's annotation colour through raw, adopt no colour taxonomy — becomes a lane-4 screening must.

## Rulings that shaped the screens

Recorded in each evidence file's "Standards as applied" section, in the order the operator gave them (2026-10-03 to 2026-10-04):

1. Machine surfaces are the guard's roster (`hooks/pretooluse_guard.py:11-23`); `system/` outside `system/propagations/` and `system/bibliography.json` is hand-edited.
2. Merging duplicates is Zotero's own behaviour and is not judged in an add-on (#183).
3. Approval gates and unmonitored backups count for nothing: a confirm dialog, a preview, a backup line or git history nobody watches does not make a write safe.
4. Written values must be right by construction: by identifier from an authoritative source, or a lossless format change. Removals only by a definite test (an exact placeholder, a nonexistent file, an exact duplicate kept on the item). A re-key passes because lifecycle detects it and `propagate` repairs it.
5. A component is judged on what it adds beyond ordinary editing: for Obsidian, beyond editing the open note; for Zotero, beyond commands the person runs on the items they selected. Obsidian's own vault operations (rename with link update, move, delete, and creating a note by following a link or from a menu) are app behaviour. A direct edit to one specific note shown in another view (a Bases cell, a checkbox in a query result) is editing that note. A handler that only inserts into the open note is open-note editing. This holds only because research-vault detects machine-surface changes whoever makes them; closing the detection gaps (#203–#212) and the capture monitor (below) are part of this spec.
6. **Selection: include anything that aids one of the five workflows and does no harm** (2026-10-04; supersedes §1's original "one add-on per job"). The five workflows: research; analysis and reports; personal knowledge management; long-form writing; daily logs. The step map gains steps for analysis/reports and knowledge management. Harm is an unconfined counted path under ruling 5, a load failure, or a destructive write. Two add-ons whose writes fight each other are not both declared.
7. **An OKF conformance break is accepted where the value justifies it**, as a row in the deviation register (`docs/agents/okf-conformance.md`) together with the verify exemption or type mapping that keeps the commit gate open for that plugin's files (2026-10-04).
8. **A redistribution licence decides only how an Obsidian plugin is declared**: seeded (vendored in `.obsidian/`, licence must permit it) or recommended (the person installs it; declared settings; doctor observes). It is not harm (2026-10-04).
9. **Agent access to Zotero is research-vault's own client** (`research_vault/zotero.py`); an add-on whose job is agent access is not declared (2026-10-04).

### Build verdict: a research-vault library module (decided 2026-10-06)

**Verdict: `build`**, tier **mature tool** (`docs/agents/sourcing.md`: the high bar), home #140, designed in its own spec after this one.

**Jobs.** (1) Identifier completion and verification: DOI, PMID and PMCID, looked up only by identifier from an authoritative source and written to Zotero's native fields. (2) Checking an item's bibliographic fields (pages, issue, volume, date, venue, creators) against the registry record for its identifier. Both run as an audit over the whole library that reports a worklist with item keys, with an optional repair of what the audit found.

**`floor_failed`: screen A's must A3 part (1)** — every value written comes from an authoritative source looked up by identifier, or is a lossless format change — met by no candidate for these jobs in every path it offers:

- **DOI Manager 2.2.0** — every menu command first fills an empty DOI from a Crossref metadata query taken without an identifier check, and no setting removes it (rows 6–7; #217).
- **DOI Fix** — Retrieve takes a single OpenURL hit unchecked; Update validates against Crossref only and replaces a valid DataCite DOI with a title match (row 8).
- **PMCID fetcher** — its automatic job writes Extra back from a stale snapshot, losing concurrent edits, and its tag fetch sends a PMCID as a PMID, attaching an unrelated article's MeSH headings (row 5; #213, two production items affected).
- **Linter for Zotero** — `require-doi` fills from a Crossref match on the item's own metadata, unchecked; its extra-zeros helper shifts page and issue ranges (row 9; #197, #200, six production page ranges and one issue range shifted).
- **ZotMeta** — takes a DOI or arXiv ID from the first matching string in the PDF's text and overwrites title and creators from it (row 11; #214).
- **No candidate checks existing fields against the registry record** for job (2); Meta Refresh corrects from the record but does not report a disagreement as a finding, and passes A3 only with five non-default keys (row 12).

**Form: a script plus a skill** (operator, 2026-10-06). A CLI verb in `research_vault` performs every Zotero write — the README's rule that the agent composes and explains while the CLI writes — reusing `research_vault/zotero.py`, the capture ledger, findings and acknowledgement, and the repository's tests and mutation gate. A skill on top carries the judgement rules cannot (for example, whether a borderline registry record is the same work). The local API applies every PATCH with `fromJSON(json, {strict: false})` (Zotero 10.0.5 `server_localAPI.js:1983`), re-running Zotero's normalisation over the record; every write therefore runs a pre-flight that computes what that normalisation would change and refuses or plans around it. The module's spec opens by measuring that round trip on the test instance against a sample of real items.

**Rejected form: research-vault's own Zotero plugin.** Writing in-process (`item.setField`, `saveTx`) would avoid the PATCH normalisation and live in Zotero's UI, but: a second codebase in a second language outside pytest, the mutation gate and CI, testable only against a running Zotero; an `.xpi` to ship with version caps, an update channel and a human install step; the common scaffolding (zotero-plugin-toolkit) carries the unprompted-install route (#199); and agents could drive it only through an endpoint, a remote write route the rulings count against it.

**Transition.** Until the module ships, the add-ons above that §1 declares stay declared for their jobs. When it ships, DOI Manager and the PMCID fetcher leave the table, Meta Refresh drops to optional, and the README table and doctor rows change with them.

## §3 Observe: detection, the capture monitor and infrastructure (in progress)

Design input: `…-section-3-designs.md` (six reviewed cluster designs) and `…-section-3-research.md` (the technical questions resolved against code, documentation and measurement). Approved 2026-10-17 unless marked pending:

- **Commit hook (#203).** It never stages. It runs the fixer — `stamp-type --paths` plus the link normaliser — on staged files and refuses the commit if the fixer changed any; re-running the commit passes. A stray wikilink refuses the commit. Dead or ambiguous link targets become "resolve by hand" findings so commits cannot loop; anchored claim blocks are skipped.
- **Capture monitor.** Holds at commit and at publish: publish re-verifies every commit since the last publication, so a `--no-verify` commit is still caught. It holds every snapshot field except tags, plus dropped or swapped attachments and changed identity; Extra is held whole. Tag-only changes are filed as one non-blocking summary row per capture run.
- **`fulltext/` edits (#207)** hold publish (the folder is gitignored).
- **`wiki/` hand edits (#212)** (operator, 2026-10-17, option C): a content edit to a compiled page refuses the commit until it is sealed or acknowledged; a change consisting only of link targets that now resolve to a renamed file (a definite test through the link resolver) reseals itself. Sealing updates both research-vault's page record and the compile tool's recorded `content_sha256`, since the tool refuses to recompile a page whose bytes no longer match it (`compile.py:283-286`). `.base` and `.canvas` files under `wiki/` are hashed with the pages.
- **Merges (#183)** are solved in this spec: a merge maps the loser's citation key to the survivor's through `propagate`.
- **Agent shell writes (#193).** Detection is the boundary. The seed carries Claude Code `Edit(...)` deny rules for the guard's roster (measured: they refuse redirects, `cp`, `mv`, `rm -r`; `python3 -c`, `perl -i` and `git checkout` still write), and doctor checks the rules against the roster. Acknowledgements are not restricted to the person's terminal (operator, 2026-10-17); an `ack` is therefore only as strong as the process that writes it, which the vault guide states.
- **Lane 4's skill screen** fails a skill that writes a machine path other than through a CLI verb or `transaction apply`, or bypasses the commit gate.
- **Zotero tags (#195).** `zotero-tags` keeps Zotero's list exactly; `tags` carries a slugged copy Obsidian can read (no `zotero/` prefix).
- **Field names (#188)** fold to Zotero's base names (an import-spec amendment), so an item-type change is not read as a field removal.
- **Component problems close publish**: drift and harmful states found by doctor's cold checks, which capture runs and files per component, including active excluded add-ons.
- **Copyleft plugins** are recommended, not vendored, with their `data.json` seeded (it survives a later community install and updates).
- **Seed location and scaffold.** The seed lives at `templates/obsidian/`, copied once; an existing `.obsidian/` is left alone. Obsidian's own trust prompt is the consent step; setup never calls `plugins:restrict on`.
- **#202**: the open-questions view becomes a core Search block. **#194**: PyYAML with OKF's reference loader, failing closed if absent. **#196**: a bibliography entry changes only when its note re-renders, with a CSL hash in the note as backstop.
- **Reserved files and litter**: empty index or log files are valid; one shape rule covers every folder; the fixer repairs root `log.md`; `.DS_Store` and AppleDouble files are excluded and gitignored; `type: fulltext` is reserved.
- **The component register** opens at lane 5. **Retraction Watch by PMID** is decided with #185, not here.
- **Corrections to §1 from the research:** ZotMeta is excluded (its writes conflict with the PMCID fetcher's); ZotMoov declares `enable_automove=false`; Attachment Scanner's trash options fire on any modify, so it is safe only once #189 lands; Linter's `lint.onAdded=true` needs a live check; a plugin update breaks byte-for-byte pins, which is expected drift.
- **#172 is carried here** (operator, 2026-10-17): the rule against quoting unlicensed sources moves into `docs/agents/sourcing.md`, widened to inline fragments, as part of the sourcing-screen method this spec ran; it lands before lane 4.
