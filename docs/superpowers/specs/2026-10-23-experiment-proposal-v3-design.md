# Design: experiment-proposal v3, usable by agents, checked where it can be

Date: 2026-10-23, revised the same day after the comparison with hutzelmann/thesis-proposal-skills (`docs/research/2026-10-23-thesis-proposal-skills-comparison.md`). Status: approved in brainstorming, awaiting spec review. Branch: `experiment-proposal-v3`. Supersedes `docs/superpowers/specs/2026-10-14-experiment-proposal-v2-design.md` where it changes it; every v2 decision not named here stands. The v2 spec gets `Disposition: superseded-by: 2026-10-23-experiment-proposal-v3-design.md (the landing date; every decision v3 does not name stands)` under its title when this spec lands.

## Why

The plugin's second use, on the author's own proposal (the Bloom response-length study, 15 to 23 October 2026), was the first with full material and a comparison against another process. Four findings drive this release:

1. Agents could not run the skills. All four are user-invoked only, so an orchestrating agent re-ran each `SKILL.md` by hand from a pasted path, and the design decisions lived outside the brief until the brief was back-filled.
2. `lit-search` was hard to use across rounds: Semantic Scholar's search endpoint answered HTTP 429 on every keyword query after the first (its graph endpoints answered both snowball rounds), the snowball output was not valid YAML (an unquoted title split across three lines), each round was 40 to 360 KB, and the second round had no way to drop the records already judged. DBLP returned nothing because our four queries ANDed six to eight terms as prefixes; it is not a defect ("health coach" returns 178 records, "health coach empathy" none).
3. The draft checker mis-measured two things the course rule asks for: an ACM-numbered reference list (`[1] ...` lines) counted as one entry, and `--references` counted the whole list while the rule covers the literature review, so the author had to widen the bounds.
4. The review's most expensive manual steps, cross-section consistency of numbers and the search for leftover placeholders, are mechanical to search and only their judgment needs a reader.

The comparison added: upstream's lit-search scripts moved to v0.9.0 (`1666e69`) with a 429 retry (present since before our pin), an output-size warning, a one-seed snowball default and arXiv hardening, so re-vendoring beats rebuilding those; their review carries an earlier round forward, which ours loses; and our attribution overstates how freely their six substance tests were restated.

The lens is unchanged: the plugin produces the course proposal and is judged by it.

## Decisions

| Question | Decision |
| --- | --- |
| Agent use | Skills become model-invocable by name with a name-only description and no trigger phrases; each `SKILL.md` gains an Agent run paragraph placed before Steps. Codex keeps `allow_implicit_invocation: false` pending the test in section 5. |
| Review carry-forward | `review` reads an existing `proposal/review.md` first and keeps its confirmed attestations, waivers and item 3.1 values; earlier fails are re-checked. |
| Checker references | `[n]` lines count as entries; `--references A-B` checks distinct citations inside the Literature Review section; the list total is an informational stderr line. A citation with no list entry is a defect (item 3.3); an uncited entry is informational. |
| Checker reports | `draft --numbers` and `draft --placeholders` print reports with locations; `review` reads them for the cross-section row and item 13.5. No declared constants, no new brief shape. |
| Checker word count | Unchanged (headings, title block, and tables count; references and appendices do not); documented in the README as the conservative reading. |
| Attested rows | `not confirmed` is an accepted result on attested items only. |
| Review record | `review.md` records, verbatim, the research questions and hypotheses it judged; a later pass prints an informational line when they changed. |

Upstream: one issue, then one pull request for the YAML escaping. No DBLP issue. |
| Ethics board | Not consumed by `review`. If `proposal/ethics-review.md` exists, item 12.3's row and the hand-off seed list name it with the count of revision entries not yet marked Applied. |

| Codex | Kept and tested; mirror the Claude behavior (callable by name, triggered by nothing). |

Out of scope, considered and rejected: one combined CLI (renames a script every reference file cites, for no shape change); `review` parsing the ethics board's revision list (no checked shape, imports rules the lens does not ask for); declared constants in the brief (a shape that can go stale); a draft-writing skill (the Bloom prose was written by agents with project-made tools outside the plugin, and the course text has no rule against AI-written prose; the non-goal is the author's choice and the next release revisits it on purpose); upstream's eval harness pieces (scratch config isolation, model pin, rubric graders, personas), a plugin CHANGELOG, and README troubleshooting, all deferred to a later release and listed in the comparison report.

## 1. Invocation and agent mode

Frontmatter of `design`, `review`, `lit-search`: `disable-model-invocation` removed; `description` is one line that names the skill and what it produces, with no trigger phrases:

- design: "Invoked by name: settles a controlled experiment's design decisions in numbered rounds and freezes them in proposal/design-brief.md."
- review: "Invoked by name: checks a written experiment proposal against its frozen design brief and the checklist, writes proposal/review.md."
- lit-search: "Invoked by name: searches scholarly indexes and snowballs from seed DOIs for a literature review's sources; appends judged DOIs to proposal/notes/lit-search-judged.txt."
- the-ethics-board (vendored): the flag is removed and the description becomes "Invoked by name: rehearses an ethics-committee review of the study and writes proposal/ethics-review.md." as a second marked local edit, with the provenance comment updated.

**Agent run.** Each `SKILL.md` gets a paragraph headed Agent run, placed after Files and before Steps, and every step that waits ends with "(an agent run does not wait; see Agent run)": design step 3 and step 7's freeze, review steps 2, 3 and 6. An agent run is one the caller declares ("no human will answer" or an agent calling by name), not a headless invocation as such, since every headless conversation begins with `claude -p` without `--continue`. In an agent run:

- `design` marks every unanswered frontier item `provisional` with the recommendation standing in, leaves the brief `open`, ends at step 6, and prints "brief open, N provisional; the user freezes it with /experiment-proposal:design". When item 1.1 is weak or missing it writes no recommended research question: interactively it asks for the question in the user's words or prints `/oss:research-grill idea` (with the install commands when absent, reusing review's detection); in an agent run it stops with that message. Recommendations for items 6.1 and 6.2 cite a source from the material or a looked-up fact, never a direction of the agent's own.
- `review` records attested items (3.1, 5.2, 13.1, 13.4) as `not confirmed`, takes the item 3.1 values an earlier `review.md` records, else the course defaults, applies no fixes, ends at step 5, and prints the `not confirmed` rows and "the user picks fixes with /experiment-proposal:review".
- `lit-search` and `the-ethics-board` return their report and end at their last step.
- One context, and the owning skill: a skill does its steps in one conversation, and when the next step belongs to another skill it names that skill rather than doing its work.

README: an "Agent use" paragraph after Commands with the by-name call, the declared agent run, and the closing lines; the headless paragraph stays; lit-search's Writes column names the judged file and `--out`.

Codex: `agents/openai.yaml` unchanged for now. The Codex test (section 5) counts a skill as admitted only when the explicit mention `$experiment-proposal:<skill>` loads it with no `rg`, `find` or `cat` of the plugin cache in the transcript (the 0.2.0 by-name review reached the skill only after the model searched the cache). Absence from Codex's Available skills list is expected under `allow_implicit_invocation: false`. If the mention fails, the four yaml files flip to `true` and rely on the name-only description; the README records which.

## 2. The checker

`scripts/check_proposal.py` stays standard library, Python 3.11 or later, no network, no writes. Every defect carries `rule` (a short slug) and `item` (the checklist ID that owns it) in text and `--json`; informational lines go to stderr and never into `--json`.

- `LIST_ITEM` also matches `^\[\d+\]` followed by a space, so ACM-numbered reference lines are entries.
- `draft --references A-B` checks the count of distinct citations in the Literature Review section: `[n]` numbers between its heading and the next heading of the same or higher level, split on commas and ranges inside one bracket; when no bracketed numbers occur there, `(Surname, year)` or `Surname [year]` keys, de-duplicated. The section is the one matching the second name in `--sections` (default "Literature Review"). Stderr: `references: <N> entries in the list`. For `[n]` lists, a number cited anywhere in the body with no list entry is a defect under item 3.3; an entry never cited is an informational stderr line.
- `draft --numbers`: after blanking `[n]` brackets, inline code and heading numbers (such as "## 4 Participants" or "C.2") without shifting offsets, and skipping the References section, scans body and appendices for a number within six words of a keyword from a fixed list (participants, N, minutes, min, session, items, sequences, turns, words, `$`, `%`) and prints, grouped by keyword, each distinct value with its locations (heading and line). Exit 0 always; `--json` gives `{"numbers": [{"keyword", "value", "locations": [...]}]}`. It judges nothing; the unit fixture plants a citation bracket next to "participants" to prove the masking.
- `draft --placeholders`: lists `TODO`, `TBD` and all-caps bracketed placeholders with heading and line; with `--placeholder-list "<heading>"` it also reports placeholders used but not listed under that heading and listed but unused. Exit 0 always; `--json` honored. `review` reads it for item 13.5.
- `review`: `not confirmed` joins the accepted results, valid only on the rows of items 3.1, 5.2, 13.1 and 13.4; on any other row it is a defect "attested result on a draft-checked item". The Summary line counts it under Fail. A new optional section `## Judged` holds the verbatim research questions and hypotheses the pass judged; the checker accepts it between Items and Cross-section consistency.
- Word count unchanged.

`references/review.md`: the Items rules name `not confirmed`; the Cross-section section says the `--numbers` report is the search and the reviewer's lines are the findings; the Judged section is described; the carry-forward rules of section 4 are stated. `references/brief.md`: unchanged.

## 3. lit-search: re-vendor, then wrap

Order: the re-vendor comes first; the wrapper is written against v0.9.0's output and stderr.

- Re-vendor the nine scripts at `1666e69` (v0.9.0) with updated provenance headers, the pin in THIRD-PARTY-NOTICES, ATTRIBUTION and the test constant. Gains since our pin: the `candidates: N (L lines, C characters on stdout)` size line, `--limit-per-seed` default 5 and one seed per call, arXiv over HTTPS with a feed-root guard and retry, UTF-8 output everywhere, type-only exception notes. The 429 retry (two retries, 3 s then 6 s, in `common.py`) was already present at our pin. Still missing upstream at HEAD: quoting of strings on output (`_yaml_scalar` unchanged), so titles with embedded newlines still break the YAML.
- New `skills/lit-search/scripts/litsearch.py`, ours, standard library, Python 3.11 or later, the only script the skill names. Subcommands mirror the vendored ones (`search "<query>" --limit N`, `snowball <DOI> --direction both --limit-per-seed 5`), plus `--exclude <file>`, `--compact` (default from round 1), `--out <file>`, `--dblp-query "<two or three terms>"`.
  - Per-source attribution: it imports the vendored modules in-process and calls their federate, expand and enrichment functions with the same signatures, so each record keeps its source tag and the summary can report `<source>(<returned>, <kept after exclude>) query="<query>"`; the vendored scripts' own stderr notes are relayed verbatim. (A subprocess per source is the fallback if the imports prove unstable; the implementation plan decides on the first run.)
  - Retry: when Semantic Scholar's search note reports HTTP 429, re-run that source alone once after 60 seconds, or skip it and say so; no whole-command re-run, which would re-hit the four other indexes.
  - Lenient parse: any line that does not start with `- id:` or an indented `key:` continues the previous scalar, quoted or not; records are de-duplicated by DOI, then by normalized title where there is no DOI; every string is re-emitted with `json.dumps(value, ensure_ascii=False)`, a valid YAML double-quoted scalar.
  - Exclude file `proposal/notes/lit-search-judged.txt`, one record per line: `<DOI or title> | <kept or rejected> | <one-line reason>`. The wrapper reads only the first field, matching DOIs with the vendored `clean_doi` and titles with `normalize_title` (84 of the 575 records in the saved rounds had no DOI). The skill seeds the file from the draft's reference list before round 1 and appends every judged record after each round.
  - Compact output keeps `title`, `author` surnames, `issued` year, `container-title`, `DOI`, and `abstract` truncated to 300 characters.
  - DBLP: the wrapper leaves `dblp` out of the main call's `--sources` and runs it separately with `--dblp-query`; SKILL.md step 3 asks for the short query.
- SKILL.md steps 2 to 4 call the wrapper, snowball one seed per call at 5, name the exclude file and the judging rule (one judging context per round; a coverage clause in the stop rule: a snowball round that adds nothing ends the search only after every kept seed has been expanded once), and tell the agent never to redirect script output into the working tree except through `--out` under `proposal/notes/`. The key file stays outside the repository or gitignored.
- Upstream (hutzelmann/thesis-proposal-skills): open an issue first, as their README asks, reproducing the unquoted-title break against v0.9.0; then one pull request to `develop` carrying an `openspec/changes/<id>/` folder made with their CLI, whose `proposal.md` ends with a `Changelog:` line, escaping line breaks and control characters in `_yaml_scalar`, with a synthetic fixture and their test suite passing. No DBLP issue.

## 4. Review carry-forward, ethics cross-reference, attribution, docs, version

- `review` step 1 reads an existing `proposal/review.md`: confirmed attestations (`confirmed by the user, YYYY-MM-DD`) and the item 3.1 values are kept; waivers are kept with their dates; every earlier `fail` row is re-checked and marked `resolved (fix N applied)` or stays `fail`; the Judged section is compared and a changed research question prints an informational line. The checker accepts `resolved (fix N applied)` as a result.
- `review` step 4: if `proposal/ethics-review.md` exists, count the numbered entries under "The Revision List" not followed by a line beginning "Applied"; item 12.3's row ends with "; ethics-review.md: N revisions open"; the hand-off seed list gains "the N open ethics revisions". Absent file: nothing printed. The checker ignores the clause.
- `the-ethics-board` `SKILL.md`: a marked local edit of two lines under What This Skill Produces asking that each revision entry, when revisited, gains an "Applied YYYY-MM-DD: ..." or "Author: ..." line. This overrides the v2 non-goal "editing vendored text beyond marked frontmatter edits"; the pm-claude-skills row of THIRD-PARTY-NOTICES, its ATTRIBUTION paragraph, the provenance header and the test that asserts a single frontmatter edit are updated to name both edits.
- Attribution correction: THIRD-PARTY-NOTICES ("Ideas restated without copying text"), ATTRIBUTION ("Ideas only, no text reproduced") and the checklist's provenance note change to "closely paraphrased from `shared/guidelines/guidelines.md`, some clauses verbatim", naming items 13.6 to 13.11; the MIT notice already reproduced covers the text.
- README: Commands table gains the by-name call and the agent-run closing lines; the checker's reference lines, `--numbers`, `--placeholders`, the word-count rule and the margin it implies; the wrapper, its exclude file, compact default and DBLP query; the ethics count; version 0.3.0 and the tag.
- `plugin.json`: 0.3.0. Briefs frozen under 0.2.0 stay valid (brief shape unchanged; the older-brief rule checks headers and amendments only). Reviews written under 0.2.0 are read by the carry-forward.
- The eval README's spec pointer moves to this file.

## 5. Tests and evaluation

A vendored-body hash test pins the nine scripts to v0.9.0 and the two vendored bodies to their recorded hashes.

Agent-run bars: scenario 2 re-run with the declared agent-run signal (brief stays `open`, every unanswered item `provisional`, no freeze commit, `check_proposal.py brief` exits 0); an agent-mode review on the scenario 5 fixtures (draft unchanged by `git diff --quiet`, rows 3.1, 5.2, 13.1 and 13.4 `not confirmed`, `check_proposal.py review` exits 0, the reply ends with the closing line). New scenario 8, real material from the author's project copied to a scratch directory (never the live `proposal/` folder): `design` extracting from `docs/study-decisions.md` into a brief (compared with the hand-written brief); `review` in agent mode on `proposal.md` against the frozen brief (expect 65 rows, four `not confirmed`, the ethics count printed), then an interactive-then-agent re-run that keeps the attestations and waivers; `lit-search` round 2 with the exclude file holding round 1's records (expect the same stop-rule verdict on a smaller candidate set). Recorded without a bar.

Done when: the unit tests pass; scenarios 2, 3, 5, 6 and 7 pass their single runs or their three-run bars; the two agent-run bars pass; scenario 8 is recorded; the README matches the shipped files; the Codex result is recorded; the attribution files read as section 4 says; the v2 spec carries its Disposition line; the tag exists.
