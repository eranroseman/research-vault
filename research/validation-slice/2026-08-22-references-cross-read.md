# References cross-read — find-sources vendored surface

Date: 2026-08-22. Full adversarial method (4 lenses, independent refuters; 15 agents, 0 errors) — the follow-up slice the skills-layer audit proposed. 11 findings confirmed; refuted candidates live in the workflow journal.

## Confirmed findings

### [important] [upstream-fact] Preprint keyword-search fallback: three vendored files give three different routings

references/biorxiv.md:12 says for keyword search of bioRxiv preprints "use Semantic Scholar, OpenAlex, or CORE instead"; references/medrxiv.md:12 says "Use Semantic Scholar, OpenAlex, or PubMed" for the identical API; and references/europepmc.md:14-18 bills Europe PMC as the route that "closes the preprint gap" (SRC:"PPR"), cross-referencing biorxiv.md as if they agreed — but neither sister file mentions Europe PMC at all. medrxiv.md's PubMed recommendation is unsupported by references/pubmed.md:10, which describes PubMed as citations/abstracts for articles and never mentions preprint coverage. Our SKILL.md:28-29 and SKILL.md:82 route to Europe PMC, siding with europepmc.md and contradicting both frozen preprint files. Remedy: a vendoring-note annotation on biorxiv.md/medrxiv.md recording that the skill's routing (Europe PMC) supersedes their divergent alternative lists.

### [important] [our-wiring] SKILL.md undercounts query-string credentials: says two APIs, references document three

SKILL.md:50 states "Two of these APIs authenticate by query string, so the fetched URL *is* a credential." The vendored references document at least three: NCBI E-utilities pass `&api_key=YOUR_KEY` in the query string (references/pubmed.md:20-21, inherited by references/pmc.md:20 "Same E-utilities as PubMed" and its rate table at pmc.md:229-233), OpenAlex passes `?api_key=YOUR_KEY` (references/openalex.md:21-22), and CORE accepts `?api_key=YOUR_API_KEY` as a query-param alternative to its Authorization header (references/core.md:22-23). An agent that hand-redacts only "the two" leaks the NCBI key in provenance URLs. Mitigation already in place: scripts/\_common.py:201 REDACTED_PARAMS covers `api_key`/`apikey`/`key` generically, so anything run through redact_url is safe — which keeps this important rather than blocking. Fix is a direct SKILL.md edit (our file): count them correctly or drop the number.

### [important] [upstream-fact] bioRxiv/medRxiv `category` filter documented with three conflicting separator conventions

For the same parameter on the same API host: references/biorxiv.md:40 says "?category=neuroscience (filter by category, use underscores for spaces)"; references/medrxiv.md:53 says "?category=cardiovascular%20medicine (use URL-encoding for spaces)"; while both files' own Categories lists are hyphenated — `cancer-biology` etc. at references/biorxiv.md:170 and `cardiovascular-medicine` etc. at references/medrxiv.md:133 — and the response example at references/biorxiv.md:113 shows `"category": "cancer biology"` with a plain space. At most one request convention can be right. Severity is driven by biorxiv.md:154-159: this API accepts out-of-spec input with HTTP 200, so a wrong separator would plausibly return unfiltered or empty results silently. Remedy: vendoring note recording the conflict and, once verified against the live API, which form actually filters.

### [important] [upstream-fact] paginate.py DOI lookups loop, duplicating the record until --max-calls, then report a complete result as INCOMPLETE

paginate.py:272 advertises the biorxiv query form 'an interval (2024-01-01/2024-01-03), Nd, N, or a DOI', but the walk cannot terminate on a DOI lookup. Verified live 2026-08-22: /details/biorxiv/10.1101/2024.01.16.575895/0/json, /1/json (and the documented /na/json) all return the identical single-record collection with messages[0] = {status, category} only — no count, no total (matching biorxiv.md:131-133). So in \_rxiv_parse, reported count is None and step falls back to len(records) (paginate.py:138-139), total is None so the next_state cap at paginate.py:148-149 never fires, and next_state is always non-None: the walk (paginate.py:326-367) re-fetches the same record every page until --max-calls (default 50, ~50 s at the 1 s delay), emits 50 duplicate records, and exits 0 with 'stopped at the --max-calls limit ... the walk is INCOMPLETE' (paginate.py:327-331) — a fully-retrieved lookup mislabeled partial, burning 50 rate-limited calls. \_common.py:141-144 documents 'expected is None for ... bioRxiv DOI lookups' as a handled state, which conceals this. The N / Nd forms share the no-counts messages shape (biorxiv.md:133) and likely the same mechanism. File is frozen; remedy is a vendoring-note annotation (e.g. 'DOI/N/Nd lookups: use a direct curl or --max-calls 1') and optionally a caveat beside the SKILL.md:44 paginate row.

File is frozen; remedy is a vendoring-note annotation on openalex.md pointing the reconstruction section at scripts/openalex_abstract.py.

### [important] [upstream-fact] paginate.py error path prints the un-redacted URL — including OPENALEX_API_KEY — to stderr

skills/find-sources/scripts/paginate.py:86,88,92 — fetch() embeds the raw `url` in every RuntimeError message (`HTTP {code} from {url}`, `could not reach {url}`, `response from {url} was not JSON`). walk() catches these at paginate.py:352-353 and prints them via fail(str(error)). \_openalex_url attaches OPENALEX_API_KEY to the query string at paginate.py:210-212, and references/openalex.md:181 documents HTTP 403 on an invalid key — exactly the case that triggers the print, so a mistyped key is emitted verbatim on its first use. This contradicts the file's own comment at paginate.py:342-345 ('Record and log the redacted form only') — true for the provenance list (:345-348) and --dry-run (:444), false for the error path — and the house posture that redact_url strips credentials from provenance (scripts/\_common.py:193-220). Escalation: SKILL.md:81's four-state table routes outages into prose reports, and the natural prose source for 'could not complete' is this stderr line, so the key has a realistic path into a pasted report, violating SKILL.md:50's 'never paste an un-redacted URL into a report'. Distinct from ruled audit finding C-3 (research/validation-slice/2026-08-22-skills-layer-audit.md:203-215), which covers only SKILL.md:50's API count and hand-redaction parameter list. File is vendored-frozen; remedy is a vendoring-note annotation (SKILL.md:11) warning that paginate.py stderr may carry an un-redacted URL and must be redacted before quoting.
