# Design: experiment-proposal v3, usable by agents, checked where it can be

Date: 2026-10-23, revised the same day after the comparison with hutzelmann/thesis-proposal-skills (`docs/research/2026-10-23-thesis-proposal-skills-comparison.md`). Status: approved in brainstorming; reviewed 2026-10-24 (docs/research/2026-10-24-experiment-proposal-v3-spec-review.md) and amended the same day. Branch: `experiment-proposal-v3`. Supersedes `docs/superpowers/specs/2026-10-14-experiment-proposal-v2-design.md` where it changes it; every v2 decision not named here stands. The v2 spec carries `Disposition: superseded-by: 2026-10-23-experiment-proposal-v3-design.md (2026-10-24; every decision v3 does not name stands)` under its title, added when this spec landed.

## Why

The plugin's second use, on the author's own proposal (the Bloom response-length study, 15 to 23 October 2026), was the first with full material and a comparison against another process. Four findings drive this release:

1. Agents could not run the skills. All four are user-invoked only, so an orchestrating agent re-ran each `SKILL.md` by hand from a pasted path, and the design decisions lived outside the brief until the brief was back-filled. Told to, that agent also wrote `confirmed by the user` into `review.md` with no user present.
2. `lit-search` was hard to use across rounds, and contributed nothing the proposal kept: 0 of its 28 references came from the skill (18 of them are cited in the Literature Review), and three kept candidates were never read. Semantic Scholar's search endpoint answered HTTP 429 on every keyword query after the first, five rounds across about 17 minutes (kw2 16:41:57, kw3 16:42:12, kw4 16:58:02, kw2b 16:58:35, kw3b 16:59:08 on 2026-10-17, -0500, the write times of the saved round files, read 2026-10-24; the project's lit-search note, `proposal/notes/lit-search-2026-10-17.md`:21-22, :160-162 and :165, records the five 429s without times), while its graph endpoints answered both snowball rounds; the snowball output was not valid YAML (an unquoted title split across three lines); each round was 40 to 360 KB; and the second round had no way to drop the records already judged. DBLP returned nothing because our four queries ANDed six to eight terms as prefixes; it is not a defect ("health coach" returns 178 records, "health coach empathy" none; DBLP publ API `@total`, probed 2026-10-23).
3. The draft checker measured the reference list, as item 5.1 then said, while the course rule covers the literature review, and it counted an ACM-numbered reference list (`[1] ...` lines) as one entry, so the orchestrating agent widened the `--references` bounds to make the run pass.
4. The review's most expensive manual steps, cross-section consistency of numbers and the search for leftover placeholders, are mechanical to search and only their judgment needs a reader; the interactive review passed the cross-section row while the consent form and Appendix H still said 36 participants where the body said 52, and passed item 8.9 on the placeholder `[NO-SHOW EXTRAS]` as its quote.

The comparison added: upstream's lit-search scripts moved to v0.9.0 (`1666e69`) with a 429 retry (present since before our pin), an output-size warning, a one-seed snowball default and arXiv hardening, so re-vendoring beats rebuilding those; their review carries an earlier round forward, which ours loses; and our attribution overstates how freely their six substance tests were restated.

The lens is unchanged: the plugin produces the course proposal and is judged by it.

## 1. Invocation and agent mode

Frontmatter of `design`, `review`, `lit-search`: `disable-model-invocation` removed; `description` is one line, a double-quoted YAML scalar (it holds a colon), that names the skill and what it produces, with no trigger phrases, and ends with the sentence that measurably stopped unprompted delegation to the subagent, "Not for unprompted use."; `design`, `review` and `lit-search` add `argument-hint: "[agent] [path or need]"`. This supersedes v2's "frontmatter form unchanged":

- design: "Invoked by name: settles a controlled experiment's design decisions in numbered rounds and freezes them in proposal/design-brief.md. Not for unprompted use."
- review: "Invoked by name: checks a written experiment proposal against its frozen design brief and the checklist, writes proposal/review.md. Not for unprompted use."
- lit-search: "Invoked by name: searches scholarly indexes and snowballs from seed DOIs for a literature review's sources; appends judged records to proposal/notes/lit-search-judged.txt. Not for unprompted use."
- the-ethics-board (vendored): the flag is removed and the description becomes "Invoked by name: rehearses an ethics-committee review of the study and writes proposal/ethics-review.md. Not for unprompted use.", one marked local edit replacing the 0.2.0 flag edit. Its provenance comment names this edit, the body edit of section 4, and the upstream's state in prose, since the tests run offline and nothing can check reachability: unreachable on 2026-10-24 (`gh api` answered 404 for the repository and the user), licence and copyright as read at `f93fee74` when vendored, archived as `swh:1:rev:f93fee7459e2bf452ec9bc43163004812efba51f`; the closing line `HEADER_CLOSE` stays, as on the other vendored files, whose headers name their marked edits. The ethics board gets no Agent run paragraph and no `argument-hint`: its agent-run rule is the one sentence of the body edit, which names the token; Claude Code appends arguments as `ARGUMENTS: <value>` to a body that has no `$ARGUMENTS` placeholder, so the vendored body needs none.

**Agent run.** `design`, `review` and `lit-search` each get a paragraph headed Agent run, placed before Steps (after Files where the skill has one), and every step that waits ends with "(an agent run does not wait; see Agent run)": design steps 3, 7 (the freeze) and 8 (the amendment), review steps 2, 3, 6 and 7 (the hand-off read), lit-search steps 1 (the need) and 3 (a seed). An agent run is one whose arguments carry the token `agent`: `/experiment-proposal:<skill> agent`, or the Skill tool with `args: "agent"`; `design`, `review` and `lit-search` read `$ARGUMENTS` and treat any other argument as the material's path or the need (the ethics board's body edit names the token). Where a host passes no arguments to a skill mention (Codex), the phrase "no human will answer" in the invoking message is the fallback, a prose rule because that host offers no argument mechanism. A headless invocation is not an agent run as such, since every headless conversation begins with `claude -p` without `--continue`. In an agent run:

- `design` marks every unanswered frontier item `provisional` with the recommendation standing in and `Source: agent run, <date>` (a form `references/brief.md` lists), leaves the brief `open`, ends at step 6, and prints "brief open, N provisional; the user freezes it with /experiment-proposal:design". On an interactive resume (step 1) an entry whose Source is an agent run rejoins the frontier as `weak` and is asked in round 1. On a frozen brief an agent run stops at step 8 with "frozen brief; amendments need the user". When item 1.1 is weak or missing it writes no recommended research question: interactively it asks for the question in the user's words or prints `/oss:research-grill idea` (with the install commands when absent, reusing review's detection and its agent-run branch); in an agent run it stops after step 2's open brief with that message, marking nothing provisional (every design-tree item stands on 1.1). Recommendations for items 6.1 and 6.2 cite a source from the material or a looked-up fact, never a direction of the agent's own, a prose rule because the checker reads no Decision or Rationale wording (v2) and whether a source fits is a judgment; scenario 8's copy A reads the result.
- `review` records attested items (3.1, 5.2, 13.1 and 13.4) as `not confirmed` and never records one as `pass`, a prose rule held by the scenario 5 agent-run bar: the checker cannot tell an agent run from an interactive one, and a header marker saying which would be written by the agent the rule binds, so no mechanism was available; a confirmation an earlier `review.md` carries survives as text inside the row (`- **3.1** not confirmed: earlier review.md read confirmed by the user, 2026-10-15`). It takes item 3.1's values from the earlier file's `Checker:` line, else the course defaults; applies no fixes, so step 6 is skipped; and its step 7 hand-off read, when `~/.claude/plugins/installed_plugins.json` cannot be read, takes the absent form, its first line replaced by "research-grill install not checked.". The reply carries the `not confirmed` rows, the closing line "the user picks fixes with /experiment-proposal:review", then the hand-off in full, which ends it as step 7 asks.
- `lit-search` stops at step 1 with a one-line ask when neither the arguments nor the brief's Open items name the need; at step 3 it skips snowballing and says so when no seed is known and picks the two or three DBLP terms from the need itself; it returns its report and ends at its last step.
- `the-ethics-board` names a missing input and proceeds with the study as described, writes `proposal/ethics-review.md` and ends at its last step.
- One context, and the owning skill: a skill does its steps in one conversation, and when the next step belongs to another skill it names that skill rather than doing its work, a prose rule because which skill's steps a conversation runs shows only in its transcript, which scenario 8's records read.

README: an "Agent use" paragraph after Commands with the by-name call, the `agent` token and the Codex phrase, and the closing lines; the headless paragraph stays; lit-search's Writes column names the judged file and `--out`.

Codex: `agents/openai.yaml` unchanged for now. The Codex test (section 5) counts a skill as admitted when the explicit mention `$experiment-proposal:<skill>` loads it and no tool call before the load names a path under the plugin cache (the 0.1.0 Codex record, `docs/research/2026-10-13-experiment-proposal-evals/runs/installs-codex-1.md`, reached the skill only after the model searched the cache); an attempt that is not admitted (a refusal, or a load after a cache search) triggers up to two more, and one admitted attempt admits the skill; unlike the scenarios' all-three rule, the question is whether the mention can load the skill at all. Absence from Codex's Available skills list is expected under `allow_implicit_invocation: false`. If all three attempts fail for a skill, the four yaml files flip to `true` and rely on the name-only description; the README records which.

## 2. The checker

`plugins/experiment-proposal/scripts/check_proposal.py` stays standard library, Python 3.11 or later, no network, no writes. Every defect carries `rule` (a short slug) and `item` (the checklist ID that owns it; `null` for a `brief` or `review` shape defect no item owns) as `--json` keys, and in text as the suffix ` [<rule>; item <ID>]` after the message, so the tests' message assertions read the text before the suffix; informational lines go to stderr and never into `--json`.

- `LIST_ITEM` also matches `^\[\d+\]` followed by a space, so ACM-numbered reference lines are entries.
- `draft --references A-B` counts the distinct citations in the section named by `--review-section` (default "Literature review", matched as `--sections` names are), between its heading and the next heading of the same or higher level, in the mode the reference list sets. A list of `[n]` lines: the `[n]` numbers cited there, split on commas and ranges inside one bracket; a number cited anywhere in the body with no list entry is a defect under item 3.3, and an entry never cited is an informational stderr line. Any other list: an entry is cited when its first surname and its year both occur in the section, so `Fitts (1954)` and `Soukoreff and MacKenzie (2004)` count, and no cited-without-entry defect is reported, a surname in prose being no citation the checker can prove. Stderr: `references: <N> entries in the list`. The defect, in both modes and only when the count is outside the bounds, reads `references: the <section> cites C of the list's N entries; the template asks for A to B`, C being the list entries cited there; the scenario 5 key's D8 is this line with 14, 14, 15 and 20.
- `draft --numbers`: after blanking `[n]` brackets, inline code and heading numbers (such as "## 4 Participants" or "C.2") without shifting offsets, and skipping the References section, lists every integer of two or more digits that is not a year (1900 to 2099) and occurs twice or more in the body and appendices, plus every `$` and `%` figure, grouped by value, each occurrence with its heading, line and the six words either side, so a stale 36 sits beside the 52 that replaced it. Exit 0 always; `--json` gives `{"numbers": [{"value", "locations": [{"heading", "line", "text"}]}]}`. It judges nothing; `review` reads it for the cross-section row.
- `draft --placeholders`: lists `TODO`, `TBD` and all-caps bracketed placeholders with heading and line; with `--placeholder-list "<heading>"` it also reports placeholders used but not listed under that heading and listed but unused. Exit 0 always; `--json` honored. `review` reads it for item 13.5.
- `draft`'s supervision sentence is sought first in the appendix block whose heading contains "consent", at any level; only when no such block exists does it search every appendix, with the stderr note `supervision sentence found outside a consent-headed appendix`. This narrows v2's appendix-wide search to the consent form the lens names.
- `review`: `not confirmed` joins the accepted results, valid only on the rows of items 3.1, 5.2, 13.1 and 13.4; on any other row it is a defect "attested result on a draft-checked item"; the Summary line counts it under Fail. A `pass` or `pass narrowly` row whose quoted passage holds an all-caps bracketed placeholder, `TODO` or `TBD` is a defect `pass-placeholder`. The header accepts an optional fifth line, `Checker: draft [--sections "..."] --words A-B --references A-B [--review-section "<heading>"] [--supervisor "<name>"]`, the `draft` options step 2 ran, validated as that option set when present (v2's header had four lines). An optional section `## Judged`, holding the verbatim research questions and hypotheses the pass judged, is accepted between Items and Cross-section consistency; `REVIEW_SECTIONS` and the reference file's "no others" admit it.
- Word count unchanged.

`references/review.md`: the Items rules name `not confirmed` (counted under Fail) and the placeholder rule (such an item is `fail` with a `decide:` fix naming what the author must supply, or `fail (waived)` with the reason); the header shows the `Checker:` line; the Cross-section section says the `--numbers` report is the search and the reviewer's lines are the findings; the Hand-off section gains the agent-run form (the absent form with its first line replaced by "research-grill install not checked.") and its "ask the user when it cannot be read" clause names the agent-run exception; the Judged section is described; the carry-forward rules of section 4 are stated; its example `Checklist:` line moves to 0.3.0. `references/brief.md`: its example `Checklist:` line moves to 0.3.0 and the Source forms gain `agent run, <date>`; nothing else changes. `references/checklist.md` changes as section 4 says.

## 3. lit-search: re-vendor, then wrap

Order: the re-vendor comes first; the wrapper is written against v0.9.0's output and stderr.

- Re-vendor the nine scripts at `1666e69` (v0.9.0) with updated provenance headers, the pin in THIRD-PARTY-NOTICES, ATTRIBUTION and the test constant `HUTZELMANN`. Gains since our pin: the `candidates: N (L lines, C characters on stdout)` size line, `--limit-per-seed` default 5 and one seed per call, arXiv over HTTPS with a feed-root guard and retry, UTF-8 output everywhere, type-only exception notes. The 429 retry (two retries, 3 s then 6 s, in `common.py`) was already present at our pin. Still missing upstream at HEAD: quoting of strings on output (`_yaml_scalar` unchanged), so titles with embedded newlines still break the YAML.
- New `skills/lit-search/scripts/litsearch.py` (planned), ours, standard library, Python 3.11 or later, the only script the skill names. Subcommands mirror the vendored ones (`search "<query>" --limit N`, `snowball <DOI> --direction both --limit-per-seed 5`), plus `--exclude <file>`, `--compact` (default from round 1), `--out <file>`, `--dblp-query "<two or three terms>"`.
  - Per-source attribution: it imports the vendored modules in-process and calls their federate, expand and enrichment functions with the same signatures, so each record keeps its source tag and the summary can report `<source>(<returned>, <kept after exclude>) query="<query>"`; the vendored scripts' own stderr notes are relayed verbatim.
  - Semantic Scholar 429: no retry of its own beyond the vendored two (`common.py`'s 3 s and 6 s), since the five 429s span about 17 minutes (Why #2) and a wait would rest on no measured interval; the wrapper relays the degraded note, prints `semantic_scholar: skipped (HTTP 429); snowball's graph endpoints cover it`, and continues.
  - Output: the vendored functions return records, so there is no YAML to parse and the lenient parse of the earlier draft goes; the wrapper de-duplicates by DOI, then by normalized title where there is no DOI, and emits every string with `json.dumps(value, ensure_ascii=False)`, a valid YAML double-quoted scalar, never through the vendored `_yaml_scalar`.
  - Exclude file `proposal/notes/lit-search-judged.txt`, one record per line: `<DOI or title> | <kept or rejected> | <one-line reason>`. The wrapper reads only the first field, matching DOIs with the vendored `clean_doi` and titles with `normalize_title` (84 of the 575 records in the saved rounds had no DOI). Before round 1 the skill seeds the file from the reference list of the draft at the brief's `Draft:` path when that draft exists, else starts it empty, and appends every judged record after each round.
  - Compact output keeps `title`, `author` surnames, `issued` year, `container-title`, `DOI`, and `abstract` truncated to 300 characters.
  - DBLP: the wrapper leaves `dblp` out of the main call's `--sources` and runs it separately with `--dblp-query`; SKILL.md step 3 picks two or three terms from the need.
- SKILL.md names the wrapper as its only script: step 2 says which indexes it will query, step 3 calls it (snowball one seed per call at 5) and step 4 appends every judged record to the exclude file; the steps name the exclude file and the judging rule (one judging context per round; a coverage clause in the stop rule: a snowball round that adds nothing ends the search only after every kept seed has been expanded once), and tell the agent never to redirect script output into the working tree except through `--out` under `proposal/notes/`, a rule because the redirect happens in the shell the agent runs, where neither the wrapper nor a test can see it. The key file stays outside the repository or gitignored. v2's "writes nothing" for this skill ends: it writes the judged file and `--out`.
- Upstream (hutzelmann/thesis-proposal-skills): open an issue in this release, as their README asks, reproducing the unquoted-title break against v0.9.0. The pull request to `develop` (an `openspec/changes/<id>/` folder made with their CLI, whose `proposal.md` ends with a `Changelog:` line, escaping line breaks and control characters in `_yaml_scalar`, with a synthetic fixture and their test suite passing) is deferred to a GitHub issue in this repository, opened when 0.3.0 lands, because the skill contributed no reference to the proposal and the pull request serves upstream first. No DBLP issue.

## 4. Review carry-forward, ethics board, checklist, attribution, docs, version

- `review` step 1 reads an existing `proposal/review.md`: the item 3.1 values come from its `Checker:` line, the course defaults when it has none (every 0.2.0 file): an agent run uses them as they are, and an interactive run's step 2 offers them in place of the course defaults in its one question; waivers are kept with their dates; an earlier attestation is never carried as a pass: in an agent run it survives as text inside the `not confirmed` row, and an interactive run re-asks the carried rows in the step 3 batch; every earlier `fail` row on a draft-checked item is re-checked and reads `pass` with its new quote or stays `fail` (attested rows follow the rule above); the Judged section is compared and a changed research question or hypothesis prints one informational line in the reply (the skill's, not the checker's). The `(fix N applied)` marker is written only by step 6 of the pass that applied the fix; each pass numbers its fixes from 1 and carries no earlier markers, so no new result word is needed. Step 2 re-runs the `Checker:` line on every pass and the 3.1 row states today's exit status; step 5 writes the `Checker:` line with the options step 2 ran, `--supervisor` only when a name is known; the Date line is rewritten on every pass.
- `the-ethics-board` `SKILL.md`: a marked local edit of two lines under What This Skill Produces, "Write this document to proposal/ethics-review.md." and "When an input is missing and the arguments carry `agent` or the invoking message says no human will answer, name it and proceed with the study as described." This overrides the v2 non-goal "editing vendored text beyond marked frontmatter edits"; the pm-claude-skills row of THIRD-PARTY-NOTICES (which also records the unreachable upstream as section 1 words it), its ATTRIBUTION paragraph, the provenance header and the test that asserts a single frontmatter edit are updated to name both edits exactly. `review` reads nothing from `proposal/ethics-review.md`.
