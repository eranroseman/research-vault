# Evals for plugins/experiment-proposal

Run records for the plugin at `plugins/experiment-proposal/`, kept out of the shipped plugin. Spec: `docs/superpowers/specs/2026-10-23-experiment-proposal-v3-design.md` (the 0.2.0 spec, `2026-10-14-experiment-proposal-v2-design.md`, and the 0.1.0 spec, `2026-10-13-experiment-proposal-plugin-design.md`, are superseded). Every answer key under `fixtures/` was written and committed before any run. Run rule at 0.3.0: scenarios 2, 3, 5 and 6 run once each with their 0.2.0 bars as a smoke test, and a failing smoke run triggers three fresh runs judged on the all-three rule (every run meets the bar); scenario 7's four positives and the two agent-run bars run once and fall back to three fresh runs the same way; scenario 7's seven negatives run three times each on the all-three rule; scenario 8 is recorded without a bar. At 0.1.0 and 0.2.0 every scenario ran three times.

## Harness

- Every run happens in a fresh scratch project outside this repository: `tmp=$(mktemp -d) && cd "$tmp" && git init -q && git commit --allow-empty -qm init && mkdir proposal`. Fixtures are copied in and committed (`git add -A && git commit -qm fixtures`) before the first turn; nothing is run inside the repository.
- The plugin is loaded from the branch's checkout with `--plugin-dir <checkout>/plugins/experiment-proposal` (Claude Code) or from the installed plugin (Task 10's install test).
- Headless runs: `claude -p --plugin-dir <plugin> --permission-mode acceptEdits --allowedTools "Read,Edit,Write,Agent,Bash(git:*),Bash(python3:*)" "<prompt>"`, with `--continue` for the next turn of the same scenario. `design` from scratch is interactive and is driven by the author in a normal session with the plugin loaded, following `fixtures/from-scratch-answers.md`; the executor records.
- Isolation (scenarios 7 and 8 and every re-run at 0.3.0): a scratch `CLAUDE_CONFIG_DIR` whose `settings.json` is exactly `{"syncClaudeAiSkills": false, "syncClaudeAiPlugins": false, "disableClaudeAiConnectors": true}`, `ENABLE_CLAUDEAI_MCP_SERVERS=false` in the environment, login by `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`), the plugin by `--plugin-dir`, `--model claude-opus-5` (the ID the 0.2.0 rows were served; the operator's settings pin another model). Each record copies the init event's `plugins`, `skills`, `agents` and `model`, the served model from the assistant turns, the CLI version and the result event's `total_cost_usd`. Scenario 6 reads `~/.claude/plugins/installed_plugins.json` by its literal path, so it reads the operator's file under any configuration; each record says so.
- Scenario 7 is judged by `routing_predicate.py` in this folder over each saved stream (`positive <skill>` or `negative`); the fixture `fixtures/routing-utterances.md` holds the eleven utterances. Codex runs are recorded under the Installs name, `runs/installs-codex-v3-1.md`.
- Records: one file per run under `runs/`, named `<scenario>-<n>.md` for 0.1.0 runs, `<scenario>-v2-<n>.md` for 0.2.0 runs and `<scenario>-v3-<n>.md` for 0.3.0 runs, holding the date, the plugin commit, the exact command, the transcript's decisive lines, each pass-bar criterion with pass or fail, and the verdict. Relative paths only; never a home-directory path.
