## 2. Summary

- **Problem** (Section 1; Section 2): LLMs produce plausible but non-existent references; reference managers store whatever metadata they are given; database look-ups are manual and interrupt writing; commercial checkers restrict free use. The objective is an open-source, free, web-based tool that gives immediate verification of a single reference or a BibTeX batch against CrossRef, Semantic Scholar and OpenAlex, and returns validated APA and BibTeX. There are no hypotheses or research questions beyond building and describing the tool.
- **Method**: Paper type, from the calibration table: systems/tool paper. It has no evaluation family: no experiment, survey, correlational or archival study; Table 1 is a feature checklist, not a measurement. The results can therefore show what the tool is designed to do, not how well it does it. The method is the design. The application is a React and TypeScript web app in four modules: LaTeX-command filtering, BibTeX parsing, multi-source search, presentation and export (Section 3 ¶1). The cascade (Algorithm 1; Figure 1): filter LaTeX; fetch the top three CrossRef candidates; query Semantic Scholar if none; pick a best match and score it; detect issues; if the score is below 70 or any issue exists, query Semantic Scholar and OpenAlex, intersect the three author lists, add 10 to the score when at least two authors are confirmed, flag authors outside the intersection as suspect; compute a final confidence; generate APA and BibTeX; return exists (score above 50), confidence, issues, outputs and sources. Similarity is normalized Levenshtein on lowercased alphanumeric strings (Eq. 1); authors are matched by family-name containment; fabricated authors are guessed from capitalized query tokens matching nothing else (Section 3, page 6 ¶2). Confidence follows Eq. (2) when title similarity exceeds 80 but author similarity is below 90, and Eq. (3), an average of title, author, journal and year similarity plus a bonus of 0 to 10, for well-matched structured input; issues carry penalties of 10 to 20 points each; footnote 2 says the values were calibrated empirically. Usage (Section 4): one text box with quick and batch modes; batch runs sequentially at 800 ms intervals with progressive results; corrected BibTeX can be downloaded or copied.
- **Results**: No quantitative results. The only tabulated content is Table 1. CheckIfExist is ticked for bibliography formatting, BibTeX export, immediate validation, hallucination detection, fake-author detection, batch verification, multi-source validation, corrected BibTeX output, open source and unlimited free usage; it lacks reference organization, word-processor integration and cloud synchronization, which the four managers have (except JabRef for cloud). The six validation rows are ticked for CheckIfExist alone. No descriptive or inferential statistics apply.
- **Discussion** (Section 4.1 ¶2; Section 5): the tool is positioned as complementary to reference managers: export a Zotero library as BibTeX, validate it, reimport the corrected entries. Practical value is set out as five use cases: authors before submission, researchers using LLMs for literature search, reviewers auditing manuscripts, publishers' submission pipelines, and bibliometric dataset cleaning (Section 5 ¶1). Limitations stated by the author: none as such; database coverage variation is acknowledged (Section 3 ¶2) but framed as the motivation for the cascade. Future work is not discussed. The conclusion (Section 5 ¶2) restates the gap, the architecture and the significance; it summarises no results because there are none.

- C3. Thresholds and outcomes. Algorithm 1 line 32 sets exists from bestScore > 50; Figure 1 separates "Verified" from "Partial Match" at "Score > 80%?"; neither threshold appears in the other. - C5. Suspect-author rule. Algorithm 1 lines 18–19: suspectAuthors = (union of the three databases' author lists) minus (their intersection), so an author absent from any one database is suspect, and the query's own author tokens are not considered.
