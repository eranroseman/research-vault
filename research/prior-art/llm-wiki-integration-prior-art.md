# LLM-wiki integration prior art: the "new source arrives → wiki updates" moment

Research note, 2026-08-16. Feeds ticket #11 Q8 (import-source integrate step). Question: when a new source is cataloged, who/what integrates it into the LLM-owned synthesis layer (atlas/), and under what discipline? Method: actual files read — prompts, schemas, code — never READMEs alone. Repos pinned: karpathy gist @ `ac46de1` (its only revision), SamurAIGPT/llm-wiki-agent @ `df636ef`, AgriciDaniel/claude-obsidian @ `1c1bc49` (same commit as adoptable-skills-audit.md — this section covers only ingest mechanics that audit did not), NousResearch/hermes-agent @ `12b1f0f`, atomicstrata/llm-wiki-compiler @ `3e17bcf`, garrytan/gbrain @ `5ef85ac`, swarmclawai/swarmvault @ `815412d`, Pratiyush/llm-wiki @ `b108889`, nvk/llm-wiki @ `b513c70`. ## 1. Karpathy's llm-wiki gist — the doctrine, not a mechanism

https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f — single file `llm-wiki.md`, 75 lines, one revision (2026-04-04). **There is no schema/CLAUDE.md in the gist** — the "schema" is a *described* third layer ("a document (e.g. CLAUDE.md …) that tells the LLM how the wiki is structured … You and the LLM co-evolve this over time", llm-wiki.md:33), and the closing note says the document is "intentionally abstract. It describes the idea, not a specific implementation" (llm-wiki.md:75). Everything below it is instantiation by others.

- **Trigger:** per-source, human-in-loop preferred: "Personally I prefer to ingest sources one at a time and stay involved … But you could also batch-ingest many sources at once with less supervision" (llm-wiki.md:37).
- **Integration scope:** the ingest flow "writes a summary page in the wiki, updates the index, updates relevant entity and concept pages across the wiki, and appends an entry to the log. A single source might touch 10-15 wiki pages" (llm-wiki.md:37). Update-existing-pages is core doctrine, not optional: the LLM "integrates it into the existing wiki — updating entity pages, revising topic summaries, noting where new data contradicts old claims" (llm-wiki.md:11).
- **Placement:** `index.md` is the routing device — "the LLM reads the index first to find relevant pages, then drills into them. This works surprisingly well at moderate scale (~100 sources, ~hundreds of pages) and avoids the need for embedding-based RAG infrastructure" (llm-wiki.md:47).
- **Contradictions:** flagged at ingest ("the contradictions have already been flagged", llm-wiki.md:13) and re-checked at lint (llm-wiki.md:41). No mechanism specified.
- **Log:** append-only, grep-parseable prefix `## [date] ingest | Title`; `grep "^## \[" log.md | tail -5` (llm-wiki.md:49).
- **Idempotency / runaway protection:** none specified. Query answers are deliberately filed back into the wiki (llm-wiki.md:39) — synthesis compounds by design.

Maintenance: idea file; never updated since posting. Every implementation below cites it.

## 2. SamurAIGPT/llm-wiki-agent — two integration lanes with different safety properties

https://github.com/SamurAIGPT/llm-wiki-agent — 3,375 stars, pushed 2026-08-10, MIT. The closest faithful instantiation of the gist. Critically it has **two lanes that share CLAUDE.md but not discipline** — do not conflate them.

**Lane A — agent lane** (CLAUDE.md read by Claude Code; AGENTS.md is the same text de-branded, verified by diff). Ingest is a 10-step per-source workflow (CLAUDE.md:70-80): read source fully → read `wiki/index.md` + `wiki/overview.md` for context → write `wiki/sources/<slug>.md` → update index → update overview "if warranted" → update/create entity pages → update/create concept pages → "Flag any contradictions with existing wiki content" → append log → post-ingest validation ("check for broken `[[wikilinks]]`, verify all new pages are in `index.md`, print a change summary"). The source-page template carries a `## Contradictions` section ("Contradicts [[OtherPage]] on: …", CLAUDE.md:107-108). Placement is index+overview-driven; the agent *can* read existing entity pages before updating them but no step mandates it (inferred gap). `.claude/commands/wiki-ingest.md` restates the same steps.

**Lane B — scripted lane** (`tools/ingest.py`, also the cron path in `docs/automated-sync.md`): one LLM call per source (litellm, `max_tokens=8192`) returns a single JSON object containing *full page contents* for source page, entity pages, concept pages, overview, index entry, log entry, plus a `contradictions` string list (ingest.py:207-238). The context given to that call is index + overview + **the 5 most-recent source pages by mtime** (`build_wiki_context`, ingest.py:63-75) — existing entity/concept pages are never shown. Consequence (inferred but mechanical): "update/create entity pages" is a **blind full-file overwrite** — `write_file()` replaces whatever accumulated content the entity page had (ingest.py:254-260), and contradiction checking sees only the last 5 sources. Contradictions are printed to console (ingest.py:273-277), not persisted anywhere structured. Post-ingest `validate_ingest()` checks broken wikilinks + unindexed pages, report-only (ingest.py:101-141).

- **Idempotency:** none in practice. `sha256(source, truncate=16)` is computed and *printed only* — never checked (ingest.py:199-202; grep: no other use). `update_index()` inserts under the section header with no dedupe (ingest.py:89-98), so re-ingesting duplicates the index entry and log entry; the source page itself overwrites by slug. `tools/refresh.py` does hash-check staleness against `graph/.refresh_cache.json` — but ingest never writes that cache, so the **first `refresh` run re-ingests every source** (cold-cache amplification), each pass re-duplicating the index (refresh.py:78-91 + inferred).
- **Doc-vs-code mismatch:** `append_log()` actually *prepends* ("Prepend a log entry to wiki/log.md (newest-first)", tools/_utils.py docstring) while CLAUDE.md:79 says "Append" — this silently breaks the gist's `grep | tail` recipe the repo itself documents (CLAUDE.md:263).
- **Runaway pressure, not protection:** the prompt demands "Aggressively convert key people, products, concepts and projects into [[Wikilinks]] … Omitting [[ ]] for known terms is a failure" (ingest.py:226); `tools/heal.py` then auto-generates entity pages for anything linked 3+ times without a page, from ≤15 × 800-char mention snippets via haiku (heal.py) — generation begets generation. The nightly automation (`docs/automated-sync.md`) chains batch ingest + heal with no human gate.
- **What breaks (issue tracker):** #73 `file_to_md` overwrote a sibling .md and deleted the source, "then reports success" (fixed); #54 heal.py used unsanitized LLM output as filenames — path traversal (fixed); #47 first-run batch validation false positives; #48 (open) concedes `log.md` is operation-level with no per-claim source anchors, so a later session cannot verify which source backed a contradiction flag.

Maintenance: active; recent commits are star-chart churn plus real fixes.

## 3. AgriciDaniel/claude-obsidian — staged transaction integration (focused re-read)

@ `1c1bc49` (v2.1.0, 10,941 stars). Ledgers, capture, BM25 internals, and hooks are covered in adoptable-skills-audit.md §2; this section is only the inbox→wiki *integration* mechanics from `skills/wiki-ingest/SKILL.md`, `agents/wiki-ingest.md`, `skills/wiki/references/operation-transactions.md`, and `provenance.md`.

- **Trigger:** per-source or bounded batch — but always **one transaction per agreed batch** ("Draft a single `claude-obsidian.transaction.v1` bundle with `operation_type: ingest` for the whole agreed batch", SKILL.md). Before any processing: agree scope and budgets — "source count, source bytes/pages, existing-page reads, generated pages, and network requests. For a large batch, choose a bounded first tranche instead of promising exhaustive processing" (SKILL.md).
- **Idempotency, three layers (documented):** (1) pre-flight — "Compute SHA-256 for each available payload and check `.raw/.manifest.json` plus the source ledger for unchanged input" (SKILL.md, Analyze step 1); (2) per-target — "Record SHA-256 preconditions for every target. Use one write per path" (SKILL.md); apply fails with exit 75 if the vault changed underneath (operation-transactions.md); (3) operation — "Reapplying an identical bundle with the same ID is a no-op; a different bundle must use a new ID" (SKILL.md).
- **Placement:** *not* retrieval-driven. Grep of `skills/wiki-ingest/` and `agents/wiki-ingest.md` finds zero references to the BM25/`wiki-retrieve` machinery — placement is "Read `wiki/hot.md`, `wiki/index.md`, active methodology settings, and only the relevant existing pages. Default to five existing pages per source; raise the budget explicitly when needed" (SKILL.md step 4). The **compilation-value gate** decides whether the atlas changes at all: "Create or expand a canonical page only when the source adds durable synthesis, navigation, a decision, or a reusable connection beyond the captured source. A concise, searchable source may need only its source/ledger record or a no-op; do not paraphrase merely to create pages" (SKILL.md step 3).
- **Update discipline — orchestrator/worker split:** parallel workers are read-only ("They must not write vault files, reserve addresses, edit manifests, or update ledgers", SKILL.md); each returns a draft packet with, per proposed target, `action: create | replace`, `expected_sha256` (null only for verified-absent paths), purpose, and complete content or a precise patch (agents/wiki-ingest.md, Output). Workers must "Propose the smallest set of creates and updates. Reuse existing pages and aliases before proposing new pages" (step 6). Apply is preview-gated: `transaction inspect` → show user "create/replace paths, raw captures, claim assessments, contradictions, and skipped items" → `transaction apply --approved-plan-sha256`, where the approval hash binds the exact reviewed plan (SKILL.md; operation-transactions.md). "Canonical replacements or an expanded scope require explicit review."
- **Coupled writes (documented invariant):** every ingest transaction couples pages + source/claim ledger records + "at least one active methodology index or MOC for every canonical page create or removal" + one batch log entry + refreshed hot cache; `wiki/index.md` only "when it is an active catalog," `overview.md` only "when the high-level picture changed" (SKILL.md).
- **Contradictions:** extracted during analysis (SKILL.md step 6); workers "Flag conflicts rather than silently resolving them" (agents/wiki-ingest.md step 8); the claim ledger preserves contradictory evidence with `contested` assessment; high-risk accepted claims need two independent sources (provenance.md).
- **What breaks (issues, open):** #148 — the frontmatter `type` vocabulary is declared four disagreeing ways and the executable router "rejects 6 of the 8 types" the docs mandate; reporter's vault drifted to "126 pages of `type: session`", a value the spec doesn't list. This is the sharpest observed placement failure in the whole survey: *when routing vocabulary and docs diverge, the agent picks one and the vault silently forks*. Also #163 (lint walks `.raw/` as link candidates, inflating findings), #160 (`wiki-lock.sh` inoperative on macOS — advisory locking never engages), #157 (iCloud corrupt runtime state), #155 (`.raw/` is the only copy of ingested sources — backup gap), #154 (multi-machine convergence undefined).

Maintenance: active through 2026-08-01; large open-issue surface, mostly platform/portability.

## 4. NousResearch/hermes-agent `skills/research/llm-wiki/` — the disciplined prompt-only instantiation

https://github.com/NousResearch/hermes-agent — 231,419 stars, MIT, pushed 2026-08-16. Skill v2.1.0, `skills/research/llm-wiki/SKILL.md` (507 lines; the directory contains **only SKILL.md** per the contents API — `SCHEMA.md` is a per-wiki file the agent *generates* from a template embedded at SKILL.md:109-213). Explicitly "Based on Andrej Karpathy's LLM Wiki pattern." All gates below are prompt conventions — nothing is runtime-enforced (documented structure; the fragility is inferred).

- **Trigger:** per-source with a distinct **bulk mode** ("Bulk Ingest", SKILL.md:386-394): "Read all sources first → Identify all entities and concepts across all sources → Check existing pages for all of them (one search pass, not N) → Create/update pages in one pass (avoids redundant updates) → Update index.md once at the end → Write a single log entry covering the batch."
- **Orientation-first rule (CRITICAL, every session):** read `SCHEMA.md` + `index.md` + last 20-30 `log.md` entries "before doing anything"; for 100+-page wikis also `search_files` the topic "before creating anything new" (SKILL.md:72-95). Stated purpose: prevents duplicate pages, missed cross-references, convention drift, repeated work.
- **Placement — page thresholds (SCHEMA template):** "Create a page when an entity/concept appears in 2+ sources OR is central to one source; Add to existing page when a source mentions something already covered; DON'T create a page for passing mentions … Split a page when it exceeds ~200 lines … Archive a page when its content is fully superseded" (SKILL.md:179-184). Ingest step ③ makes the duplicate check load-bearing: "This is the difference between a growing wiki and a pile of duplicates" (SKILL.md:275-276).
- **Update discipline:** existing pages get additive updates ("Add new information, update facts, bump `updated` date", SKILL.md:281) — not regeneration. Every new/updated page needs ≥2 outbound `[[wikilinks]]` *and* "Check that existing pages link back" (SKILL.md:283-284). Closed tag taxonomy, add-before-use: "every tag on a page must appear in this taxonomy. If a new tag is needed, add it here first" (SKILL.md:176-177). Per-paragraph provenance markers `^[raw/articles/source.md]` required on pages synthesizing 3+ sources (SKILL.md:126-129). Confidence frontmatter where absence is itself a lint signal: pages citing a single source with no confidence field are surfaced "for either finding corroboration or demoting" (SKILL.md:348-350).
- **Contradictions — Update Policy:** "1. Check the dates — newer sources generally supersede older ones. 2. If genuinely contradictory, note both positions with dates and sources. 3. Mark the contradiction in frontmatter: `contradictions: [page-name]` 4. Flag for user review in the lint report" (SKILL.md:207-213); plus `contested: true` so "weak claims don't silently harden into accepted wiki fact" (SKILL.md:148-149).
- **Index/log:** mandatory index entry per page + "Total pages" count in the index header; log entry per action listing "every file created or updated"; log rotation at 500 entries → `log-YYYY.md`; index scaling rules (>50 entries per section → split; >200 total → `_meta/topic-map.md`) (SKILL.md:236-238, 248, 292-298, 495).
- **Idempotency:** raw sources carry frontmatter `sha256` over the body; "On re-ingest of the same URL: recompute the sha256, compare to the stored value — skip if identical, flag drift and update if different" (SKILL.md:266-269); lint recomputes all raw hashes to catch drift (SKILL.md:352-355).
- **Runaway protection:** the expected blast radius is embraced ("A single source can trigger updates across 5-15 wiki pages. This is normal and desired", SKILL.md:300-301) but capped by a human gate: "Ask before mass-updating — if an ingest would touch 10+ existing pages, confirm the scope with the user first" (SKILL.md:493-494).

Maintenance: active (repo pushed daily); no skill-specific failure reports found.

## 5. atomicstrata/llm-wiki-compiler — deterministic enforcement; the compile/refresh/review machine

https://github.com/atomicstrata/llm-wiki-compiler — 1,930 stars, v1.1.0, MIT, pushed 2026-08-12, real CI. Standalone Node CLI (`llmwiki`), not a skill. The one implementation where integration rules are **runtime checks, not prompt conventions**: "Profile floors are runtime checks. Field contracts, lifecycle transitions, relation counts, evidence, and artifact requirements are enforced across page, lifecycle, workflow, import, and approval write surfaces" (README, Quality and safety model).

- **Trigger:** decoupled. `ingest` only copies into `sources/`; integration happens at explicit `compile` (batch, incremental) or `refresh --stale` (targeted repair of pages whose recorded source hashes drifted, "deliberately leaving unrelated new sources for a full compile", docs/concepts/how-it-works.mdx). `--dry-run` previews with no LLM calls.
- **Placement — two-phase pipeline:** Phase 1 extracts concepts from *all* changed sources before any write ("the compiler knows the full concept universe — including which concepts appear in multiple sources — before it commits to writing a single file"); Phase 2 generates pages, deterministically merging cross-source concepts into one page (how-it-works.mdx). Ownership (which source owns which concept slugs) lives in `.llmwiki/state.json`.
- **Update discipline:** compiler-owned regeneration — pages are rebuilt from their contributing sources, not appended to. Optional `.llmwiki/schema.json` sets per-kind minimum wikilink counts and permitted page kinds (docs/concepts/wiki-model.mdx).
- **Contradictions:** extraction emits `contradictedBy` per concept; cross-source merge takes "a pessimistic aggregate view of confidence, provenance, and contradictions" with `contradictedBy` unioned by slug (src/compiler/extraction-merge.ts:25-30); `src/compiler/provenance.ts` maps it onto frontmatter and prints compile warnings; the review policy's `contradicted` hold mode then queues such pages. The `autosci` research profile additionally declares typed `supports` / `contradicts` relations between pages (docs/configuration/autosci-profile.mdx) — the closest prior art found to our stance links.
- **Review queue (the propose-only mechanism, in code):** default is write-live; `compile --review` holds everything; a policy in `.llmwiki/config.json` is "more surgical — a normal compile writes most pages live while automatically holding back the ones that trip specific risk conditions": `low-confidence` (threshold 0.5; **pages with no confidence field are held by default**), `contradicted`, `schema-violating`, `provenance-violating` (broken/malformed citations), `all` (docs/configuration/review-policy.mdx). Config is **fail-closed**: unknown mode or corrupt config aborts compile "rather than silently disabling the policy". Held candidates record reason codes in `.llmwiki/candidates/`; "The existing live page in `wiki/` (if any) is left untouched"; rejects archive for audit. Documented gap: `query --save` is *not* policy-gated.
- **Index/log:** `wiki/index.md` is regenerated every compile (generated TOC, not hand-maintained); `log.md` append-only journal `## [ISO-timestamp] operation | description` (wiki-model.mdx).
- **Idempotency:** by construction — per-source SHA-256 vs `state.json`; "Re-running on a fully unchanged corpus completes in a few seconds with no LLM calls"; freshness states `fresh`/`stale`/`orphaned`/`unverified` surfaced by lint/status/viewer without recompiling (how-it-works.mdx).
- **Adopt-as-tool vs pattern-only for our integrate step — verdict: pattern-rich, adopt-hostile.** Output *is* Obsidian-compatible ("open the `wiki/` directory as an Obsidian vault … no additional configuration", wiki-model.mdx; `[[slug|Title]]` aliases, YAML frontmatter — verified against `examples/basic/wiki/`). But three structural mismatches make wrapping it as our integrate step wrong: (1) **page ownership** — its wiki/ is a compiled artifact owned by `state.json`; pages are regenerated from `sources/` on recompile, so an atlas page co-authored by LLM sessions and human review outside `compile` is either clobbered or falls out of ownership tracking. Our atlas is LLM-authored prose under HITL review, not a compilation target. (2) **Citation carrier** — its provenance is `^[source.md]` inline-footnote markers plus line-range citations keyed to `sources/` filenames (wiki-model.mdx; README), not `[@citekey, locator]` or `citekey#^claim-id` block addresses; its `provenance-violating` floor validates *its* marker format, so our conventions would read as violations or go unchecked. (3) **Evidence layer** — it wants sources as files in `sources/`; our evidence layer is citekey-keyed literature notes generated by the Zotero bridge, already one representation removed. **What to lift instead (patterns):** the candidates/ record shape (held page + machine-readable reason codes + archive of rejects), fail-closed review config, surgical per-risk hold modes with "missing confidence ⇒ held" as default, the fresh/stale/orphaned/unverified vocabulary computed from recorded hashes, phase-1-before-any-write batch extraction, and autosci's typed `supports`/`contradicts` relation declarations. Also noteworthy as a distribution-trust (not integration) pattern: profile templates ship as signed offline distributions — "Ed25519 signing, key rotation, and package revocation" verified via `template publish verify` from explicitly trusted taps (README, v1.1.0 release notes) — structure contracts themselves travel under signature.

Maintenance: active, versioned releases, CI, extensive docs.

## 6. garrytan/gbrain — deterministic graph wiring, an ingest gate, and a maintenance lane

https://github.com/garrytan/gbrain — 28,556 stars, MIT, TypeScript, pushed 2026-08-16. Scale-proven agent-memory brain (README claims 150K+ pages) — markdown pages in a git "brain repo" but with a **Postgres substrate** (pgvector + FTS + job queue) carrying the graph, chunks, and two epistemic tables. Four mechanisms matter for our integrate step; all verified in files.

- **Zero-LLM integration floor (deterministic self-wiring):** "Auto-link fires on every page write. No LLM calls; pure pattern matching on `[[wiki/people/bob]]` style references. New entity → new page stub → graph grows" (README.md:304); "Every `put_page` extracts entity refs from markdown/wikilinks/typed-link syntax and writes edges with zero LLM calls. Typed edges (`attended`, `works_at`, `invested_in`, `founded`, `advises`, `mentions`, …)" (README.md:313). The retrieval payoff is self-benchmarked: "P@5 49.1% … **+31.4 points P@5** over its graph-disabled variant" on a 240-page synthetic corpus (README.md:12) — documented claim, own eval harness, not independently verified. Obsidian relevance: bare basename `[[note-name]]` resolution across folders is opt-in (`link_resolution.global_basename true`, off by default; `gbrain doctor` reports how many edges you'd gain first, README.md:313).
- **Pre-write ingest gate (the placement/dedup decision as a hard rule):** `skills/brain-ingest-gate/SKILL.md`: "No content enters the brain without passing this gate. A raw `cp` or `mv` into the brain repo is a bug. … One insight, one place. If it already exists, link to it — don't clone it." Two ordered checks before any write: named-entity resolution **registry-first** ("a vector score is a floor for prose, never a gate for named things" — exact-name lookup beats similarity for named things), then a read-the-top-hit dedup decision tree (`clear-dup / plausible-dup / clear`). The gate only decides write/link/skip; the admitting skill applies page-quality rules.
- **Dream cycle — a maintenance lane decoupled from ingestion (a third trigger model):** "Cron-driven enrichment runs while you sleep: dedup people pages, fix citations, score salience, find contradictions, prep tomorrow's tasks" (README.md:307). `gbrain dream` runs "one brain maintenance cycle", cron-friendly (`0 2 * * *`), phase-selectable, `--dry-run` previews with no writes (src/commands/dream.ts header); phases include lint, backlinks, sync, synthesize, extract, extract_facts, extract_atoms, resolve_symbol_edges, patterns, enrich_thin, consolidate, skillopt (src/core/cycle.ts:105+). Two trust postures worth copying verbatim: the skillopt phase "never auto-mutates bundled skills — emits proposed.md instead for user review" (cycle.ts comment), and supersession has a pinned invariant — "the `auto-supersession.ts` 'NEVER auto-applies' invariant — the probe only emits paste-ready commands; only `consolidate` writes `valid_until` (a grep guard pins this)" (docs/contradictions.md).
- **Contradiction handling — measured, judged, never auto-resolved:** `gbrain eval suspected-contradictions` samples retrieval pairs, date-pre-filters (>30d apart skipped), LLM-judges with a 0.7 confidence floor and a persistent cache keyed on chunk hashes + model + prompt version, and reports a Wilson 95% CI headline rate with a severity rubric (low = naming, medium = stale values, high = identity/structural claims) (docs/contradictions.md). The verdict enum distinguishes real conflict from change-over-time: `no_contradiction | contradiction | temporal_supersession | temporal_regression | temporal_evolution | negation_artifact`. Posture: "The output is data — the operator decides what to act on"; every finding ships a paste-ready `resolution_command` (supersede / re-synthesize / `mark-debate` to keep both / manual review). The layered *prevention* story for curated pages: compiled-truth + timeline + source-tier boost outranks stale bulk content; `takes.active` filtering hides explicitly-superseded takes.
- **Also captured (beyond integration scope, per ticket):** `gbrain think` "composes a synthesized answer … with explicit citations to the source pages AND an honest note on what the brain doesn't know yet. The gap analysis is the differentiator: the answer tells you when a page is stale, when a claim is uncited, when two pages contradict each other, when there's a hole you should fill" (README.md:208) — prior art for a project-flow gap-analysis step. **Schema packs** are versioned, agent-authorable structure contracts (page types, typed links, auto-extracted facts; 14 `gbrain schema` CLI verbs + batched `schema_apply_mutations` MCP op with atomic file locks and an agent-identity audit log, README "Agent-authored schema"; per-mounted-brain packs govern routing, docs/what-schemas-unlock.md:100-102; `schema_lint` exists, docs/TOOL_CATALOG.md:169). The **7-verb MCP memory protocol** — `recall / remember / entity / synthesize / forget / context_pack / delta` (docs/TOOL_CATALOG.md:126-132) — is a minimal-surface precedent: every verb is zero-LLM and sub-second except `synthesize`, which is explicitly marked "[EXPENSIVE / SLOW — makes LLM calls…]". The **takes-vs-facts split** (docs/takes-vs-facts.md) keeps two epistemic layers — takes = "WHO believes WHAT, with confidence weight and time" (kinds `take|fact|bet|hunch`, multi-holder) vs facts = owner's real-time conversational memory — promoted hot→cold only through the consolidate phase "which adds proper attribution, deduplication"; "Never conflate them."
- **Adopt-as-tool vs pattern-only — verdict: pattern-only, same shape of reasoning as llmwiki but for substrate instead of ownership.** Adopting gbrain means adopting Postgres + job queue + embeddings + a server deployment ("8GB+ RAM … raw API token usage", README.md:118) as the carrier of graph/facts/takes state — our atlas is a git-diffable Obsidian vault where frontmatter and stance links *are* the state. Its contradiction machinery judges retrieval-sampled chunk pairs, not block-anchored claims; provenance is page-level citation + back-linking convention, not `citekey#^claim-id`. What to lift: (1) the deterministic zero-LLM edge pass on every write — our bridge can extract wikilink/stance-link edges and update derived indexes deterministically at integrate time, reserving the LLM for prose; (2) the ingest gate's registry-first-then-read-top-hit dedup tree as the placement preamble; (3) the dream-cycle shape for a *maintenance* lane (nightly lint + contradiction probe + staleness scoring) that is explicitly not the integration lane, with the NEVER-auto-apply invariant on anything that resolves or supersedes; (4) severity-rubric'd, paste-ready-command contradiction reports.

Maintenance: very active (pushed daily), production incident docs in-repo, self-hosted eval suite.

## 7. Sweep — additional implementations with distinct mechanisms

**swarmclawai/swarmvault** (659 stars, MIT, TypeScript, pushed 2026-06-30). Three mechanisms not seen elsewhere, all verified in code. (1) **Approval bundles + managed blocks:** generated wiki mutations are staged via `stageGeneratedOutputPages` into an approval directory with an `approvalId` before landing (packages/engine/src/sources.ts:1525, 1970-2008), and canonical pages are marked "Canonical page maintained by SwarmVault. Guided sessions stage replaceable update blocks here for approval" — with the same replaceable-block sentence on human-curated pages (sources.ts:1798-1799): a managed-sections discipline where the agent owns delimited blocks, not the page. (2) **Graph shrink guard:** a watch-mode refresh is aborted if the regenerated graph's node or edge count drops more than 25% (`DEFAULT_MAX_GRAPH_SHRINK_RATIO = 0.25`; "Graph update aborted … Re-run with --force or SWARMVAULT_FORCE_UPDATE=1 if this shrink is expected", watch.ts:33, 129-152) — the only *destructive-refresh* circuit breaker found in this survey. (3) **Candidate promotion gates, disabled by default:** candidate pages become canonical only past `minSources: 3, minConfidence: 0.8, minAgreement: 0.7, minDegree: 2, minAgeHours: 24, maxPerRun: 25` — and `enabled: false` ships as the default (candidate-promotion.ts:3-12), i.e. even the project that built automated promotion doesn't turn it on. Contradictions are claim-pair records carrying both source IDs, surfaced in per-source briefs and review pages, with `evidence_state: "conflicting" | "needs_judgment"` (sources.ts:707-758, 1209). The maintainer's ranking of what actually matters (issue #11 comment, user waydelyle): "the most valuable trust check is source provenance on nodes and edges, followed closely by graph diff and validate after compile … users complain more when they cannot prove a wiki update was grounded, complete, and non-destructive." Caveat: the *question* in #11 was posted by the same account behind llm-wiki-agent#48, which cites a nonexistent repo (see dead ends); the maintainer's answer is the primary evidence here, the question's framing is not.

**nvk/llm-wiki** (1,034 stars, MIT, Python + Claude plugin, pushed 2026-08-16 — llm-wiki.net is its site). Distinct mechanism: **ingest ≠ integrate.** `/wiki:ingest` only captures — write raw file with frontmatter (title/source/type/ingested/tags/summary), update the touched `_index.md` files, append log — then "Check uncompiled source count. If 5+, suggest `/wiki:compile`" (claude-plugin/commands/ingest.md:186-203). Article synthesis is a separate, deferred, batch `compile` step. Navigation doctrine: "Indexes are navigation. Every existing wiki-managed directory has `_index.md` with a contents table. Read indexes first, never scan blindly" and "Raw is immutable. Once ingested, sources are never modified … Explicit retraction is the exception" (AGENTS.md:113-114). Batch inbox processing routes items to topic wikis via a human-confirmed classification table (strong/weak/skip per item; ingest.md:163-184), with the operational note: "Fetch all items first (parallel if possible), classify in one pass, then process. Don't fetch-classify-ingest one at a time — that's fragile if interrupted mid-batch" (ingest.md:184). Sources the user hasn't accepted go to a `/wiki:inventory` candidate queue instead of being ingested ("A durable candidate record is better than ingesting a source the user has not accepted", ingest.md:31-36).

**Pratiyush/llm-wiki** (365 stars, MIT, pushed 2026-06-18; sources are coding-agent session transcripts). Adds maturity metadata to the standard gist workflow: mandatory frontmatter `confidence: 0.85` ("4-factor score (source count, quality, recency, cross-refs)") and `lifecycle: draft | reviewed | verified | stale | archived` (AGENTS.md:202-205) — the nearest analog to our maturity frontmatter. Hard rules: "No silent overwrites. Record contradictions, don't hide them" and "Frontmatter is authoritative" (AGENTS.md:209-212). Log auto-archives at 50KB (AGENTS.md:13). Otherwise the ingest steps mirror SamurAIGPT lane A (AGENTS.md:55-68).

**llmwikis.org handbook** (public handbook, "Last reviewed July 2, 2026"; page text verified 2026-08-16 — not an implementation, but the cleanest statement of update discipline in the ecosystem): ingest step 4-6 verbatim: "Route through index.md. Decide which existing concept, entity, and synthesis pages must be updated. Preserve and extend. Rewrite target pages so new knowledge integrates with prior content without deleting unresolved history. Record contradictions. Add unresolved conflicts to wiki/contradictions.md instead of smoothing them over." Its "Done means" bar is notable: "At least one concept, entity, or synthesis page was evaluated for update" — evaluation, not update, is the obligation. Distinct mechanism: a *central* `wiki/contradictions.md`, vs per-page frontmatter (hermes) or ledgers (claude-obsidian).

## Implications for the import-source integrate step

Everything mature in this survey separates "source landed" from "atlas changed," and gates the second. The convergent invariants — worth adopting regardless of option: (a) orientation before integration (hermes: SCHEMA+index+recent log; every system routes placement through an index, none through embeddings — even Karpathy calls the index sufficient at our scale); (b) page/claim thresholds so that **no-op is a legitimate integration outcome** (claude-obsidian's compilation-value gate; hermes' 2+-source page threshold; llmwikis.org's "evaluated for update" done-bar); (c) contradiction = flag-and-keep-both, never resolve at ingest — universally; (d) the integration writes index + log entries atomically with the page writes (claude-obsidian's coupled-writes invariant is the strongest form); (e) re-import must be a cheap no-op via content hash (hermes skip-if-identical; llm-wiki-compiler state.json; SamurAIGPT is the counterexample proving the cost).

**Option A — integrate-per-import (import-source ends with a live integrate step).** The gist's own doctrine, and lane A of SamurAIGPT/Pratiyush/hermes. Freshest context (the source was just read), contradictions surface immediately, and the human is already present at import time — matching Karpathy's stated preference for supervised one-at-a-time ingestion. Requires the hermes disciplines to be safe: orientation-first, page thresholds, mandatory read-before-update of every touched atlas page (the SamurAIGPT lane-B blind-overwrite failure is exactly what happens when the updater doesn't read the target), and a blast-radius confirm (hermes' 10+-page ask-first). Cost: one LLM integration pass per import; batch imports of N sources do N passes and miss cross-source merge opportunities (llm-wiki-compiler's phase-1 argument).

**Option B — propose-only queue (integrate step emits proposals; a separate approve step lands them).** The trust-first shape, with three working precedents: claude-obsidian's inspect→approve→apply transaction (SHA preconditions, approval hash binding, op-ID no-op), SwarmVault's approval bundles, llm-wiki-compiler's candidates/ with reason codes. Two observed cautions: full queues create friction that implementations back away from — llmwiki's *default* is write-live with review reserved for tripped risk conditions, and SwarmVault ships its promotion gates disabled — and an unapplied queue is a staleness liability. The strongest variant observed is llmwiki's **surgical policy**: write low-risk updates live, auto-hold only on named conditions (contradicted, low/absent confidence, schema violation, broken provenance), fail closed on misconfiguration. That maps cleanly onto our maturity frontmatter: proposals touching pages above a maturity bar, or carrying contradicting stance links, get held; seedling-page updates land directly.

**Option C — batch integrate-on-demand (import only catalogs; a separate integrate/compile command updates the atlas).** nvk's ingest/compile split (with the 5-uncompiled nudge) and llm-wiki-compiler's compile are the precedents; hermes' bulk mode shows the batch payoff (identify entities across all sources upfront, one search pass, one write pass — less thrash, better merges). Fits a 50-item backfill perfectly. But the failure mode is documented in the wild: SamurAIGPT's unsupervised nightly batch is where blind overwrites, console-only contradiction reports, and heal-generated page sprawl compound with nobody watching — and SwarmVault's maintainer names "destructive refresh surprises" as what shrink guards exist for. Batch integration needs a delta report (SwarmVault graph diff / shrink-guard shape) reviewed before or immediately after landing.

Two cross-cutting refinements from gbrain (§6), orthogonal to the A/B/C choice: **(i) a deterministic floor under every option** — whatever the LLM proposes, the mechanical parts of integration (extracting stance-link/wikilink edges from written pages, updating derived indexes, dedup lookups against the citekey registry and atlas index) can run as zero-LLM code on every write, which is both cheaper and lint-able; gbrain's registry-first rule ("a vector score is a floor for prose, never a gate for named things") is the right placement preamble — exact citekey/title lookup before any semantic matching. **(ii) Integration ≠ maintenance:** gbrain runs contradiction probing, staleness scoring, citation fixing, and dedup as a separate cron "dream cycle" with dry-run phases and a NEVER-auto-apply rule for supersession — a fourth lane that keeps the atlas sharp without loading those jobs onto the import path. Our lint/gate layer (#10) is that lane's natural home; the integrate step should not try to be it.

**Recommended synthesis (grounded, not novel):** make the integrate step of import-source **Option A trigger with Option B discipline** — import ends with an integration pass that *drafts* atlas updates and stance links, lands them or holds them per a surgical policy keyed to page maturity and contradiction presence, and always writes the evidence-layer record, index entry, and log entry regardless (so a held proposal never blocks cataloging — nvk's capture-vs-compile split). Keep a separate batch integrate command (Option C) for backfills, gated by a delta summary, and leave contradiction probing/staleness to the maintenance lane (gbrain's split). **Do not adopt llm-wiki-compiler or gbrain as the tool** (verdicts §5, §6) — port llmwiki's review-queue record shape, fail-closed policy config, and freshness vocabulary, and gbrain's deterministic edge pass, registry-first dedup gate, and operator-decides contradiction reports.

## Dead ends / negative knowledge

- **The Karpathy gist contains no schema, CLAUDE.md, or code** — one revision, one 75-line prose file (git log of the gist repo). Any "the gist's schema says…" claim is actually about an instantiation. The ticket's premise that the gist includes schema conventions is wrong in the narrow sense; its *description* of the schema layer is the inheritance.
- **claude-obsidian's BM25 is not wired into ingest placement** — grep of `skills/wiki-ingest/` and `agents/wiki-ingest.md` finds no retrieval references; placement is hot-cache + index + a 5-page read budget. "BM25-assisted placement" has no implementation in this ecosystem; every placement mechanism observed is index-mediated or (SwarmVault) graph-mediated.
- **No implementation anchors claims at block level.** Finest observed provenance granularity: hermes' per-paragraph `^[raw/file.md]` markers and llm-wiki-compiler's line-range citations to source files. Nothing resembles `citekey#^claim-id` stance-link addresses; llmwiki-autosci's typed `supports`/`contradicts` page relations are the nearest analog. Our block-anchored claim addressing has no donor — we build it.
- **Contradiction *resolution* has no prior art** — every system flags and preserves both sides (frontmatter, ledger, claim-pairs, or a central contradictions.md) and defers to "user review"; none defines what happens after review.
- **SamurAIGPT's hash theater:** ingest.py computes a SHA-256 per source and never checks it; refresh.py checks a cache ingest never writes. Idempotency that exists in the docs but not the code path — verify, don't trust, ingestion-hash claims.
- **SamurAIGPT `append_log` prepends** (tools/_utils.py) while its own CLAUDE.md documents append + a `tail` recipe — a live doc-vs-code drift in the most-starred faithful instantiation.
- **skyllwt/OmegaWiki does not exist** (GitHub API 404) despite being cited with an issue number in llm-wiki-agent#48; the same account opened swarmvault#11. Treat those *questions* as product-discovery marketing; only the SwarmVault maintainer's reply was used here.
- **hermes' skill directory contains only SKILL.md** — SCHEMA.md is generated per-wiki from an embedded template; there is no separate schema file to audit. All hermes gates are prompt conventions with zero runtime enforcement.
- **llm-wiki-compiler's `query --save` bypasses its own review policy** (docs/configuration/review-policy.mdx, documented) — synthesis-written-back is the unguarded write path even in the most gate-heavy implementation. Our filed-back syntheses need the same gate as ingested updates.
- **claude-obsidian #148 is the observed cost of vocabulary drift:** four disagreeing `type` declarations, an enforcing router, and a vault that silently forked into an undocumented type. Single-source the atlas frontmatter vocabulary and make the linter read the same declaration the router does.
- **hermes cites llm-wiki-compiler at `github.com/atomicmemory/llm-wiki-compiler`** (SKILL.md:502) — stale org; the live repo is `atomicstrata/`. Its trade-off note is still apt: "it owns page generation (replaces the agent's judgment on page creation)."

And its contradiction probe is deliberately excluded from the autonomous-agent surface ("NOT in the subagent allowlist — user-initiated only", docs/contradictions.md, Trust posture) — even the most automated system in this survey keeps contradiction judgment human-triggered.
