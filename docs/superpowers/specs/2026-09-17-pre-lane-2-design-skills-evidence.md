**What it does.** User-invoked entry skill (`disable-model-invocation: true`, SKILL.md:4; the only file in skills/capture-source/). It frames ingest as four steps from CONTEXT.md:32-44 — selection (the person's), add, capture, compile — and runs the mechanical ones as CLI verb calls, never Write/Edit on `literatures/`, `fulltext/`, `system/bibliography.json`, `system/propagations/`, `wiki/` (SKILL.md:9-13). §1 `add` writes a Zotero item JSON and runs `python3 -m research_vault add` (SKILL.md:15-23: Zotero consent dialog, no retry loop, `unkeyed`). §2 `capture KEY…|--all` (SKILL.md:25-46) with a nine-row outcome table in four-state vocabulary — MATCHED matched / NOOP, UNMATCHED not-admitted / no-fulltext / re-keyed / merged|trashed|deleted / database-changed, SKIPPED no-fulltext, UNREACHABLE outage — and the rule that findings are filed under check id `capture` by the CLI, never by the model (:46). §3 routes post-capture reading of `verify` (check ids `lifecycle`, `captured-set`) to `verify-citations` (:48-50). §4 `propagate` plan/apply with `--approved-plan-sha256`, writing `system/propagations/`, guarded by the `propagation` check (:52-62). §5 `compile KEY…|--all` and `compile --bundle --approved-plan-sha256` register captured sources in the tool's ledger, then hand off to the tool's wiki-ingest skill (spelled unbackticked) on `fulltext/<attachment key>.md`, then a second `capture` embeds `![[<page path>]]` from the ledger's `pages[]`; `recompile-needed` is reported by `verify` (:64-74). A four-state honesty table and the "partial reading = SKIPPED applied to reading" rule (:76-86), and a routing table to find-sources, synthesis-conventions, verify-citations, project-flow/publish, setup-vault (:88-96).
